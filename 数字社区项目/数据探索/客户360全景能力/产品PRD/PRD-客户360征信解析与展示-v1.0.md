## 1. 概述

### 1.1 需求背景

策略同学在解读人行征信报告时效率较低，主要痛点：
- 人行征信报告为 XML 格式原始数据，解读门槛高
- 缺乏结构化展示，重要信息不突出
- 无法对多份报告进行对比分析
- 无法对报告添加业务备注

### 1.2 需求目标

通过征信解析 + 结构化展示 + 对比分析 + 备注功能，提高策略同学对人行征信报告的解读效率。

### 1.3 功能范围

| 功能 | 层级 | 说明 |
|:---|:---:|:---|
| 征信解析 | 后端 | 人行征信报告 XML → 结构化数据 |
| 结构化展示 | 前端 | 解析结果的标准化展示 |
| 对比分析 | 前端 | 支持多报告版本对比 |
| 备注功能 | 前端 | 支持添加业务备注 |

### 1.4 数据来源

- **数据来源**: 征信系统（XML 文件）
- **输入格式**: 人行征信报告 XML
- **输出格式**: 结构化 JSON

## 5. 技术方案（钟离评审）

### 5.1 XML 解析方案

| 方案 | 推荐度 | 说明 |
|:---|:---:|:---|
| Jackson XML | ⭐⭐⭐ | 与 JSON 处理一致性好，注解驱动 |
| JAXB | ⭐⭐⭐ | JDK 内置，无需额外依赖 |

### 5.2 接口规范

| Method | Endpoint | 说明 |
|:---:|:---|:---|
| POST | /api/credit/parse | 征信解析 |
| GET | /api/credit/report/{id} | 获取报告 |
| GET | /api/credit/contrast/{ids} | 对比接口 |
| POST | /api/credit/notes | 添加备注 |
| GET | /api/credit/notes/{reportId} | 获取备注 |
| DELETE | /api/credit/notes/{noteId} | 删除备注 |

### 5.3 前端组件拆分

```
CreditReportView          # 主容器
├── CreditSummaryCard      # 摘要卡片
├── CreditModulePanel      # 折叠面板
│   └── CreditRiskTag     # 风险标注
├── CreditContrastSelector # 版本选择
│   └── CreditMetricCard   # 指标对比
└── CreditTrendChart       # 趋势图表
CreditNoteModal            # 备注弹窗
└── CreditNoteItem         # 备注项
```

### 5.4 性能优化

| 优化点 | 说明 |
|:---|:---|
| XML 大小限制 | < 5MB |
| 解析算法 | 流式解析（StAX） |
| 缓存策略 | Redis TTL 24h |
| 大文件 | 异步队列 |
