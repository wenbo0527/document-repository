## 三、需求背景

### 3.1 目标

数据发现域旨在帮助用户高效地发现、理解和管理企业数据资产。一期聚焦三个核心模块：**统一搜索**、**数据要素市场**、**数据资产字典**，构建数据资产的单点查找与详情查看能力。

### 3.2 痛点

1. **找数困难**：业务人员不清楚有哪些数据资产可用，数据分散在多个系统，缺乏统一的发现入口
2. **元信息缺失**：找到数据后，无法快速了解其业务含义、血缘关系和质量问题
3. **口径不统一**：同一指标/变量在不同系统中定义不一致，缺乏统一的要素管理

### 3.3 核心挑战

1. 多源异构数据的统一检索与排名
2. 指标/变量/特征三类要素的统一管理视图
3. 资产目录的多维度筛选与血缘追溯

**Story SE-002：搜索结果智能排序**

| 字段 | 内容 |
|:---|:---|
| 角色-场景-价值 | 作为用数的人，在搜索结果过多时，系统按相关性/更新时间/使用热度等维度排序，以便优先看到最相关资产 |
| 优先级 | P0 |
| 状态 | 待开发 |

**验收标准**：

1. 搜索结果默认按相关性排序
2. 支持按更新时间、使用热度切换排序维度
3. 排序切换后结果即时更新，不重新请求接口
4. 排序因子可配置

**相关性计算规则**：

| 匹配类型 | 加权系数 | 定义 |
|:---|:---:|:---|
| 完全匹配 | 3.0 | 搜索关键词与字段值完全一致 |
| 前缀匹配 | 2.0 | 搜索关键词为字段值的前缀 |
| 包含匹配 | 1.2 | 搜索关键词完整包含在字段值中 |
| 分词匹配 | 1.0 | 搜索关键词与字段分词后部分匹配 |
| 模糊匹配 | 0.6 | 搜索关键词与字段值部分字符匹配 |

**字段基础权重**：
| 字段类型 | 基础权重 | 示例 |
|:---|:---:|:---|
| 中文名/名称/标准名 | 10.0 | 表中文名、外数名称、变量中文名 |
| 英文名/编号/代码 | 8.0 | 变量英文名、接口编号 |
| 业务属性字段 | 6.0 | 指标域、业务域、主题域 |
| 描述/口径字段 | 3.0 | 表描述、外数描述、业务口径 |
| 分类/类型字段 | 2.0 | 产品分类、接口类型 |

**对象类型系数**：
| 对象类型 | 系数 |
|:---|:---:|
| 数据表（资源/资产） | 1.5 |
| 变量 | 1.3 |
| 指标 | 1.2 |
| 外部数据 | 1.1 |
| 表字段 | 1.0 |
| 业务概念 | 1.0 |

**计算公式**：最终相关性得分 = Σ(字段基础权重 × 匹配强度加权系数) × 对象类型系数

**交互说明**：

结果页顶部提供排序切换 Tab（默认「相关」/「最新」/「热门」）；点击切换时前端本地排序，无需重新请求接口；排序状态不写入 URL 参数（仅当前会话生效）。

- 系统根据缺失类型自动匹配负责人 → 创建审批流
- 负责人处理完成后 → 系统通知用户工单已处理

**验收标准**：
1. 搜索结果为空时展示"缺失数据"入口按钮
2. 点击入口弹出工单表单，支持填写：缺失类型（必选）、名称（必填）、详细描述（选填）、用途（选填）
3. 工单提交后自动匹配负责人，发送通知
4. 负责人可在工单管理页面处理工单，补充数据或标记原因
5. 工单处理完成后系统通知用户
6. 用户可在"我的工单"查看历史记录和处理状态

**交互说明**：
```
搜索结果为空
     ↓
点击"缺失数据"按钮
     ↓
弹出工单表单
┌─────────────────────────────┐
│ 缺失数据类型： [下拉选择▼]   │
│ 缺失名称：    [输入框]       │
│ 详细描述：    [文本域]       │
│ 用途：        [文本域]       │
│           [取消] [提交工单]  │
└─────────────────────────────┘
     ↓
提交成功 → 跳转"我的工单"并展示工单状态
```

**工单状态流转**：
```
待处理 → 处理中 → 待通知 → 已完成/已驳回
```

**通知机制**：
- 工单创建后通知负责人
- 工单处理完成后通知提交用户
