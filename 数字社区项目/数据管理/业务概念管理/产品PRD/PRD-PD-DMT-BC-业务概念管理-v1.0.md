## 三、需求背景

### 3.1 目标

业务概念管理旨在建立业务与技术之间的桥梁，通过业务域、业务实体、业务图谱三个维度，实现业务概念的可视化管理和业务数据的全链路追踪。

### 3.2 痛点

1. **业务与技术语言不统一**：技术人员和业务人员对同一数据有不同的理解和命名
2. **数据脉络不清晰**：数据要素与物理表之间的映射关系不透明，难以追溯
3. **跨域协作困难**：不同业务域之间的实体关系缺乏统一视图

### 3.3 核心价值

- **业务可理解**：用业务语言描述数据，降低业务与技术沟通成本
- **数据可追溯**：建立业务实体与物理表的双向映射关系
- **关系可视化**：通过图谱直观展示业务实体之间的关系

### 7.3 图谱视图

#### 7.3.1 工具栏

| 功能 | 图标 | 状态 |
|:---|:---|:---:|
| 层级筛选 | - | ✅ |
| 中心实体选择 | - | ✅ |
| 刷新 | IconRefresh | ✅ |
| 放大 | IconPlus | ✅ |
| 缩小 | IconMinus | ✅ |
| 自适应 | IconExpand | ✅ |

#### 7.3.2 图形交互

| 能力 | 描述 |
|:---|:---|
| 节点渲染 | 自定义业务节点组件（BusinessNode.vue） |
| 边渲染 | 组成、关联、继承三种关系类型 |
| 布局算法 | 基于 Dagre 的层次布局 |
| 鼠标滚轮缩放 | minScale: 0.5, maxScale: 3 |
| 拖拽平移 | panning enabled |
| 节点悬停高亮 | 阴影 + 位移效果 |
| 点击节点查看图谱 | 定位到该节点 |

#### 7.3.3 节点信息展示

| 信息项 | 描述 |
|:---|:---|
| 节点图标 | 通用图标 |
| 节点标题 | 超长自动截断 |
| 层级标签 | 客户层/账户层/业务层，颜色区分 |
| 统计信息 | 属性数量、关系数量 |

| 还款域、贷后域、产品域、风控域 | business | 橙色 #FFF7E6 |

#### 7.3.5 图谱容器样式

```css

网格线：启用
最小缩放：0.5
最大缩放：3
圆角：8px
边框：1px solid var(--color-border-2)
```
