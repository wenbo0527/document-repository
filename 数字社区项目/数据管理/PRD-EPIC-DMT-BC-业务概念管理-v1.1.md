## 三、需求背景

### 3.1 目标

业务概念管理旨在帮助企业建立统一的业务语义层，将技术元数据与业务语言打通，让业务人员能够理解和使用数据资产。

### 3.2 痛点

| 痛点 | 描述 |
|:---|:---|
| 业务语言与技术语言割裂 | 业务人员说"客户"，技术人员说"CUSTOMER表"，两者不对齐 |
| 口径不统一 | 同一个指标（如"贷款余额"）在不同系统中定义不一致 |
| 业务知识散落 | 业务知识分散在需求文档、口头沟通中，缺乏统一管理 |

### 3.3 核心挑战

| 挑战 | 描述 |
|:---|:---|
| 映射关系维护 | 业务概念与物理表的映射关系维护 |
| 版本管理 | 业务口径的版本管理和变更追踪 |
| 可视化展示 | 业务图谱的可视化展示和交互 |

### Feature 1：业务域管理 {#F-001}

**路由**: `/management/business-domain`

**类型**: 🔄 已有功能

**功能描述**：业务域是业务数据的顶层分类结构，用于组织和划分不同业务领域的数据资产。

**关联 Story**：

| Story ID | Story 名称 | 优先级 | 状态 |
|:---|:---|:---:|:---:|
| Story-BC-DOM-001 | 业务域列表 | P0 | 已上线 |
| Story-BC-DOM-002 | 新建业务域 | P0 | 已上线 |
| Story-BC-DOM-003 | 编辑业务域 | P0 | 已上线 |
| Story-BC-DOM-004 | 删除业务域 | P1 | 已上线 |
| Story-BC-DOM-005 | 查看实体 | P0 | 已上线 |

---

**Story BC-DOM-001：业务域列表**

| 字段 | 内容 |
|:---|:---|
| 角色-场景-价值 | 作为数据管理员，在业务域列表页统一查看所有业务域，了解业务域分布和归属 |
| 优先级 | P0 |
| 状态 | 已上线 |

**查询条件**：业务域名称（文本模糊匹配）、状态（启用/停用）

**数据字段**：业务域编码、名称、描述、实体数量、负责人、状态、创建时间

**验收标准**：
1. 列表页默认按创建时间倒序展示
2. 支持分页，每页20条
3. 支持按业务域名称模糊搜索
4. 支持按状态筛选（启用/停用）
5. 点击「查看实体」跳转至该业务域下的实体列表

---

**Story BC-DOM-002：新建业务域**

| 字段 | 内容 |
|:---|:---|
| 角色-场景-价值 | 作为数据管理员，创建新的业务域，对业务数据进行顶层分类 |
| 优先级 | P0 |
| 状态 | 已上线 |

**验收标准**：
1. 点击「新建」按钮弹出表单 Dialog
2. 表单字段：业务域编码（必填，唯一性校验）、业务域名称（必填）、业务域描述（选填）、负责人（选填）
3. 编码格式可配置（默认：DOMAIN_{序号}）
4. 保存前进行表单校验，校验失败禁止提交
5. 保存成功后自动关闭 Dialog，列表刷新并展示新记录

---

**Story BC-DOM-003：编辑业务域**

| 字段 | 内容 |
|:---|:---|
| 角色-场景-价值 | 作为数据管理员，修改已有业务域的信息 |

5. 保存成功后自动关闭 Dialog，列表刷新

**Story BC-DOM-004：删除业务域**

| 字段 | 内容 |
|:---|:---|
| 角色-场景-价值 | 作为数据管理员，删除不需要的业务域 |
