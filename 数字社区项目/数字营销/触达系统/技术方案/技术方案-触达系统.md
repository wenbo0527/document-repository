## 一、系统架构

### 1.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                    前端层 (Vue3 + Element Plus)              │
├─────────────────────────────────────────────────────────────┤
│  渠道管理    模板管理    触达任务    频次控制    效果分析       │
├─────────────────────────────────────────────────────────────┤
│                    服务层 (Java Spring Boot)                  │
│  渠道服务    模板服务    任务服务    频控服务    发送服务      │
├─────────────────────────────────────────────────────────────┤
│                    第三方渠道接入层                           │
│         短信(阿里云)  推送(个推)  邮件(SendGrid)  微信        │
├─────────────────────────────────────────────────────────────┤
│                    数据层                                     │
│     MySQL     Redis      Kafka       ClickHouse              │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 技术栈

| 层级 | 技术选型 | 说明 |
|:---|:---|:---|
| 前端 | Vue3 + TypeScript | 组件化开发 |
| 后端 | Java Spring Boot 2.7 | 业务逻辑处理 |
| 数据库 | MySQL 8.0 | 渠道、模板、任务元数据 |
| 缓存 | Redis 6.0 | 频控计数、热点数据 |
| 消息队列 | Kafka | 发送任务异步处理 |
| 分析引擎 | ClickHouse | 触达效果分析 |
| 渠道接入 | 第三方 SDK | 阿里云、个推、SendGrid |

## 二、数据库设计

### 2.1 渠道表 (reach_channel)

```sql
CREATE TABLE reach_channel (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    channel_code VARCHAR(64) NOT NULL UNIQUE,
    channel_name VARCHAR(128) NOT NULL,
    channel_type VARCHAR(32) NOT NULL COMMENT 'SMS/PUSH/EMAIL/WECHAT/VOICE',
    status VARCHAR(32) DEFAULT 'ACTIVE',
    config JSON COMMENT '渠道配置',
    provider VARCHAR(64),
    quota_limit INT,
    quota_used INT DEFAULT 0,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_channel_code (channel_code),
    INDEX idx_channel_type (channel_type)
) COMMENT='触达渠道表';
```

### 2.2 消息模板表 (message_template)

```sql
CREATE TABLE message_template (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    template_code VARCHAR(64) NOT NULL UNIQUE,
    template_name VARCHAR(128) NOT NULL,
    channel_type VARCHAR(32) NOT NULL,
    content TEXT NOT NULL,
    variables JSON,
    status VARCHAR(32) DEFAULT 'DRAFT' COMMENT 'DRAFT/PENDING/APPROVED/REJECTED',
    owner_id BIGINT,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_template_code (template_code),
    INDEX idx_status (status)
) COMMENT='消息模板表';
```

### 2.3 触达任务表 (reach_task)

```sql
CREATE TABLE reach_task (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    task_code VARCHAR(64) NOT NULL UNIQUE,
    task_name VARCHAR(128) NOT NULL,
    task_type VARCHAR(32) NOT NULL COMMENT 'IMMEDIATE/SCHEDULED',
    target_audience JSON NOT NULL,
    channel_codes JSON NOT NULL,
    template_codes JSON NOT NULL,
    schedule_time DATETIME,
    status VARCHAR(32) DEFAULT 'DRAFT',
    total_count INT DEFAULT 0,
    success_count INT DEFAULT 0,
    fail_count INT DEFAULT 0,
    owner_id BIGINT,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_task_code (task_code),
    INDEX idx_status (status)
) COMMENT='触达任务表';
```

### 2.4 频控规则表 (freq_control_rule)

```sql
CREATE TABLE freq_control_rule (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    rule_code VARCHAR(64) NOT NULL UNIQUE,
    rule_name VARCHAR(128) NOT NULL,
    rule_type VARCHAR(32) NOT NULL COMMENT 'GLOBAL/CHANNEL/TEMPLATE/AUDIENCE',
    channel_codes JSON,
    time_window INT NOT NULL COMMENT '时间窗口(分钟)',
    max_count INT NOT NULL,
    status VARCHAR(32) DEFAULT 'ACTIVE',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_rule_code (rule_code)
) COMMENT='频控规则表';
```

### 2.5 发送记录表 (send_record)

```sql
CREATE TABLE send_record (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    record_code VARCHAR(64) NOT NULL UNIQUE,
    task_id BIGINT,
    channel_code VARCHAR(64) NOT NULL,
    template_code VARCHAR(64) NOT NULL,
    user_id VARCHAR(64) NOT NULL,
    phone VARCHAR(32),
    content TEXT,
    status VARCHAR(32) DEFAULT 'PENDING' COMMENT 'PENDING/SUCCESS/FAILED',
    send_time DATETIME,
    error_code VARCHAR(32),
    error_message TEXT,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_task_id (task_id),
    INDEX idx_user_id (user_id),
    INDEX idx_send_time (send_time)
) COMMENT='发送记录表';
```

## 四、核心流程

### 4.1 消息发送流程

```
用户 → 创建任务 → 提交审批 → 审批通过 → 启动执行 → 发送服务 → 渠道服务 → 发送结果
```

### 4.2 频控检查流程

```
发送请求 → 频控服务 → Redis计数检查 → 通过/拒绝 → 记录发送
```

## 五、非功能性设计

### 5.1 性能设计

| 指标 | 目标 | 方案 |
|:---|:---|:---|
| 消息发送延迟 | ≤ 5秒 | Kafka异步+批量发送 |
| 模板查询响应 | ≤ 1秒 | Redis缓存 |
| 数据统计延迟 | ≤ 10分钟 | ClickHouse实时写入 |

### 5.2 高可用设计

| 方案 | 说明 |
|:---|:---|
| 服务多实例 | 后端服务多实例部署 |
| 渠道降级 | 渠道异常时自动切换 |
| 发送重试 | 失败消息自动重试 |

### 5.3 安全设计

| 方案 | 说明 |
|:---|:---|
| 内容审核 | 消息内容合规检查 |
| 数据隔离 | 多租户数据完全隔离 |
| 操作审计 | 所有操作记录日志 |
