## 三、产品概述

### 3.0 触达名词解释

| 术语 | 解释（公式化表达） |
|:---|:---|
| **推送量** | MA系统推送名单的推送量 |
| **接收量** | 触达系统接收MA名单成功量（逻辑上100%，即MA推送名单中触达接收成功量） |
| **下发量** | 触达下发AI外呼厂商（短信厂商）成功量（触达下发量中的推送量） |
| **下发成功率** | 下发量 ÷ 接收量 |
| **触达成功量** | AI外呼接通量、短信发送成功量（触达量中的触达成功量） |
| **触达成功率** | 触达成功量 ÷ 下发量 |
| **触达失败量** | 触达厂商返回失败状态（推送量中的失败量包含推送失败、厂商外呼失败，如短信发送失败、AI外呼未接通等） |
| **触达进行中** | 触达系统已推送，厂商未返回失败量（推送量中的系统已推送） |
| **策略级频控** | 对单个策略在一定时间内的执行频率进行控制，如每日下发5次 |
| **全局频控** | 跨策略、跨场景、跨渠道的全局触达频率控制，如同一用户7天内收到触达不超过3次 |
| **黑名单** | 记录禁止触达的用户信息列表，如手机号、身份证号等，用于限制对特定用户的营销触达 |

**数据流转公式**：
```
推送量（MA）
    ↓
接收量（Touch接收）≈ 推送量（100%）
    ↓
下发量（厂商成功接收）≤ 接收量
    ↓
触达成功量（用户实际收到）≤ 下发量
```

**成功率链路**：
```
下发成功率 = 下发量 ÷ 接收量
触达成功率 = 触达成功量 ÷ 下发量
```

### 3.1 产品定位

Touch 触达系统是一个**多渠道用户触达管理平台**，支持短信、AI外呼、人工外呼等多种触达方式。系统提供渠道管理、模板配置、策略制定、发送记录查询等完整功能，帮助运营人员高效管理和执行各类触达任务。

### 3.2 目标用户

| 用户角色 | 使用场景 |
|:---|:---|
| **运营人员** | 管理模板、查看发送记录、配置触达策略 |
| **管理人员** | 查看触达数据概览、审核模板、管理供应商 |
| **技术人员** | 管理系统配置、供应商、频控规则 |

### 3.3 核心价值

1. **多渠道统一管理**：短信、AI外呼、人工外呼一站式管理
2. **模板复用**：支持模板创建、审批、复制，提高效率
3. **策略自动化**：配置触达策略，支持实时和批量触达
4. **数据追溯**：完整的发送记录和明细查询

### 3.4 系统边界

│                            │                             │

│         （mock厂商/百应/九四/人工坐席）               │

**数据流向**：
- **上游接入**：营销画布实时/离线推送名单至 Touch
- **下游对接**：Touch 对接各供应商（短信/AI外呼/人工外呼）执行触达任务

**触达节点说明**：
- 触达节点是 MA（营销自动化）系统中的配置节点，用于配置对应渠道的策略ID
- 运营人员在 MA 中配置触达节点，指定使用 Touch 系统中的哪个策略模板
- MA 通过触达节点触发 Touch 执行触达任务

### 3.5 需求背景与痛点

当前业务中，触达工作面临以下挑战：

| 痛点 | 说明 | 影响 |
|:---|:---|:---|
| **渠道分散，操作割裂** | 短信、AI外呼、人工外呼各一套系统，运营人员需要在多个平台间切换 | 操作效率低，易出错 |
| **模板管理混乱** | 模板无统一管理，审批流程缺失，模板复用率低 | 重复开发，资源浪费 |
| **数据追溯困难** | 各渠道数据分散，无法统一查询和分析 | 效果评估难，决策缺乏依据 |
| **频控缺失** | 无全局频控规则，容易对同一用户过度触达 | 用户体验受损，投诉率上升 |
| **黑名单管理不规范** | 各渠道黑名单独立维护，数据不一致 | 用户已退订仍收到短信，合规风险 |

**解决方案**：通过 Touch 触达系统，实现多渠道统一管理、模板标准化、数据集中查询、全局频控和黑名单整合。

### 3.6 触达流程示意

```
┌─────────────────────────────────────────────────────────────────────┐
│                          Touch 触达系统                              │
│                                                                     │
│   1. 名单接入                                                        │
│      ┌──────────────┐    名单推送     ┌──────────────┐              │
│      │   营销画布   │ ──────────────→│  Touch 接收   │              │
│      └──────────────┘                 └──────┬───────┘              │
│                                             │                       │
│   2. 黑名单过滤                                                      │
│      ┌─────────────────────────────────────────────┐               │
│      │         用户黑名单检查 → 命中则跳过触达        │               │
│      └─────────────────────────────────────────────┘               │
│                       ↓ 通过                                         │
│   3. 多渠道频控                                                      │
│      ┌─────────────────────────────────────────────┐               │
│      │    按渠道+场景检查触达频率 → 超限则跳过触达    │               │
│      └─────────────────────────────────────────────┘               │
│                       ↓ 通过                                         │
│   4. 策略匹配                                                        │
│      ┌─────────────────────────────────────────────┐               │
│      │         匹配触达策略 → 选择供应商渠道          │               │
│      └─────────────────────────────────────────────┘               │
│                       ↓                                              │
│   5. 触达执行                                                        │
│      ┌──────────────┐ ┌──────────────┐ ┌──────────────┐            │
│      │  短信渠道    │ │ AI外呼渠道   │ │ 人工外呼渠道 │            │
│      │  (mock厂商)    │ │  (百应/九四)  │ │  (人工坐席)  │            │
│      └──────────────┘ └──────────────┘ └──────────────┘            │
│                       ↓                                              │
│   6. 状态回传                                                        │
│      ┌─────────────────────────────────────────────┐               │
│      │         供应商回传状态 → 记录触达明细          │               │
│      └─────────────────────────────────────────────┘               │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**流程说明**：

| 阶段 | 说明 |
|:---|:---|
| 1. 名单接入 | 营销画布实时/离线推送触达名单至 Touch |
| 2. 黑名单过滤 | 系统自动进行黑名单检查，命中则跳过触达 |
| 3. 多渠道频控 | **按渠道（短信/AI外呼/人工外呼）+ 场景（营销/催收/通知）检查触达频率**，超限则跳过 |
| 4. 策略匹配 | 根据名单属性匹配对应的触达策略模板，确定发送渠道 |
| 5. 触达执行 | 将任务下发至对应供应商（短信/AI外呼/人工外呼）执行 |
| 6. 状态回传 | 供应商回传发送状态，系统记录触达明细和发送记录 |

**多渠道频控规则说明**：

| 维度 | 说明 | 示例 |
|:---|:---|:---|
| 控制渠道 | 短信 / AI外呼 / 人工外呼 | 短信渠道频控 |
| 控制场景 | 营销 / 催收 / 通知 等 | 营销场景频控 |
| 一级场景 | 经审冷-停催 / 经审冷-黑催 / 经催热-意向 等 | 经催热-意向场景 |
| 控制规则 | N 天内触达 M 次 | 7 天内触达 1 次 |

**频控执行逻辑**：
1. 用户收到触达请求时，系统查询该用户的历史触达记录
2. 按"渠道 + 场景 + 一级场景"维度计算最近 N 天内的触达次数
3. 若触达次数已达上限（≥ M 次），则跳过本次触达
4. 若未达上限，则记录本次触达，继续执行后续流程
