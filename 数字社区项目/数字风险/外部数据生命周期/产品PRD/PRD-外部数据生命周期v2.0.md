## 三、需求背景

### 3.1 目标

建立外部数据全生命周期管理体系，实现从外数采购到下线全流程的可视化管控，提升数据管理员、采购人员、业务用户的协作效率。

### 3.2 痛点

1. **全流程管理层面**：流程分散、状态不透明
   - 业务用户：无法实时跟踪外数申请进度
   - 采购人员：对账结算效率低，差异处理流程繁琐
   - 数据管理员：难以统筹监控全流程状态，无法实现全局管控

2. **核心对账环节**：人工依赖度高，痛点突出
   - 具体痛点：易出现名称匹配错误、免费量统计遗漏，手工计算繁琐，对账差异追溯困难
   - 需求方向：需通过系统功能实现自动化对账，并留存完整对账明细

3. **预算与合同管控**：缺乏可视化工具，风险预警依赖人工
   - 具体痛点：预算超支、消耗过慢等异常情况无法及时预警，没有打通预警通知的信息闭环

4. **基础资产档案**：信息不完整，支撑能力不足
   - 信息缺陷：档案中缺少对账相关字段，且未实现元数据规范化管理
   - 直接影响：难以基于完整档案开展外数资产的价值评估，同时无法满足合规管控要求

### 3.3 名词解释

| 名词 | 解释 |
|:---|:---|
| 外数资产 | 指从外部供应商采购、用于业务开展的数据资源（含基础数据、校验数据等） |
| 外数生命周期状态 | 引入中、已上线、待评估、已下线 |
| 征信机构 | 百行、朴道、钱塘、学信网、各地的大数据集团、总行 |
| 供应商 | 学信网、京东、字节、各地的大数据集团 |
| 外数产品 | 学信网_学历模型 |
| 平台产品 | 字节-融担、蚂蚁-借呗一期 |

## 四、需求范围

### 4.1 功能范围

本次需求聚焦**外部数据生命周期管理**，核心覆盖以下模块：

| 核心模块 | 核心职责 | 关键输出 |
|:---|:---|:---|
| 生命周期总览 | 聚合各模块数据与状态，提供流程可视化、KPI监控、待办聚合 | 全景视图、异常预警、待办列表、节点跳转 |
| 预算管理 | 预算预警、合同管理、核心对账结算、对账痛点解决 | 预算燃尽报告、合同管理、对账核销 |
| 档案管理 | 外数档案/对账元数据维护、权限配置、关联资产管理 | 完整外数档案、元数据清单、权限记录、资产图谱 |
| 外数评估 | 质量/风险评估、评估报告生成、规则维护 | 质量评分、风险等级、标准化评估报告 |
| 服务管理 | 外数服务构建，服务任务追踪 | 外数相关服务发起，任务追踪，常规调用量监控等 |

### 4.2 角色定义

| 角色 | 核心定位 | 核心对接模块 |
|:---|:---|:---|
| 数据管理员 | 全流程统筹管控，负责基础配置、权限分配、数据维护 | 生命周期总览、档案管理、评估中心 |
| 采购管理 | 核心业务落地，负责预算监控、合同管理、对账结算全流程 | 预算管理、生命周期总览 |
| 业务用户 | 需求发起与使用反馈，负责外数申请、服务使用、数据提交 | 服务管理、生命周期总览 |
| 访客用户 | 公开信息浏览，无操作权限 | 生命周期总览（公开视图） |

### 4.3 不在本次范围内

- 外数服务模块（后续版本设计）
- 外数评估模块（后续版本设计）
- 与第三方系统的深度集成（仅预留接口）

## 附录A：档案状态流转规则

| 当前状态 | 触发条件 | 状态变更结果 |
|:---|:---|:---|
| 引入中（初始） | 在档案管理模块新建外数，录入基础信息并提交 | 状态固定为"引入中"，仅生成初始档案 |
| 引入中→上线中 | 1.关联已生效合同 2.补充借款信息 3.补充落库表信息 | 状态更新为"上线中"，开放业务调用权限 |
| 上线中→待评估 | 1.效果追踪连续3周期未达标 2.业务反馈异常 3.落库数据一致性问题 | 状态变更为"待评估"，生成"外数评估"待办任务 |
| 待评估→上线中 | 完成评估报告，选择"恢复上线" | 状态回退为"上线中" |
| 待评估→已归档 | 完成评估报告，选择"归档处理"并补充原因 | 状态变更为"已归档"，冻结业务调用权限 |
