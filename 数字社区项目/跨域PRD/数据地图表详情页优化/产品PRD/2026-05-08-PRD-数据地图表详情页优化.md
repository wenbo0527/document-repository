## 三、需求背景

### 3.1 目标

优化数据地图（dfd-app）表详情页的信息架构，将使用说明区分为表级和字段级，强化加工逻辑和版本信息的展示能力，提升用户对数据资产的理解效率。

### 3.2 痛点

1. **使用说明层次不清**：现有"使用说明"Tab 混含表级和字段级说明，用户无法快速定位到关心的字段信息
2. **字段变更追溯困难**：无法看到字段的历史变更记录，排查问题耗时
3. **加工逻辑展示不直观**：SQL 需要展开才能查看，且未区分任务级和字段级加工逻辑
4. **版本变更日志缺失**：表版本信息只有版本列表，无法直接查看完整的变更 log 文件

### 3.3 核心挑战

1. **跨模块协同**：需求涉及 dfd-app（展示层）和 dmt-app（管理侧），需要两端联动修改
2. **版本数据建模**：需要确定如何存储和展示"最近2个版本"的字段变更记录
3. **log 文件接入**：表版本信息的变更 log 文件需要确认存储位置和访问方式
4. **Git log 解析替代注册**：数据管理侧正在推进"自动抽取替代手动注册"，本次优化需兼容 Git 作为数据源的场景

---

## 四、需求范围

### 4.1 功能范围

本次需求聚焦 **dfd-app 表详情页使用说明 Tab 和表版本信息 Tab 的优化**，核心覆盖：

| 模块 | 优化项 | 说明 |
|:---|:---|:---|
| **使用说明 Tab** | 表级使用说明 | 保留现有表级别使用说明 |
| **使用说明 Tab** | 字段级使用说明 | 新增字段级 Tab，展示最近2个版本的字段变更，支持查看变更日志（抽屉方式） |
| **加工逻辑 Tab** | 任务级 SQL | 直接展示任务级 SQL，移除折叠交互 |
| **表版本信息 Tab** | 变更日志入口 | 新增"查看变更日志"按钮，支持查看完整 log 文件 |

### 4.2 不在本次范围内

- 表结构 Tab（fields[] 列表）的功能优化
- 数据预览、关联关系、血缘关系 Tab 的修改
- **新建表注册**（dmt-app 侧已不支持新建，仅支持编辑和上下架）
- 字段级别的权限控制

### 9.4 注册流程的演进

| 阶段 | 形态 | 核心能力 |
|:---|:---|:---|
| **当前** | 纯手动注册 | 用户填表单，录入所有字段 |
| **过渡期** | 手动 + 自动混合 | 手动注册为主，自动抽取为辅 |
| **目标态** | 自动抽取为主 | CI/CD 自动同步，Git/DB → dmt，无手动注册 |

**目标态下保留的能力**：
- ✅ **编辑**：修正 Git/DB 自动抽取错误的 owner、description、category
- ✅ **上下架**：人工控制表的状态（active/inactive/archived）
- ✅ **版本追溯**：Git log 提供完整的变更历史

> ⚠️ 本次需求需兼容 **Git 作为数据源** 的场景，版本信息和变更日志应优先从 Git log 解析获取。
