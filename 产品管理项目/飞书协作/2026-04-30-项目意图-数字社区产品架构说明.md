## 一、项目背景

### 痛点
传统需求管理靠文档，信息散、追踪难、版本乱。PRD 写是一套，开发出来是另一套。

### 目标
用 AI + 图数据库 + 飞书，把产品管理从「手工活」变成「智能系统」。数字社区是 PRD 的 Demo 实现，补充文档难以表达清楚的细节。

### 目标用户
| 用户 | 核心场景 |
|:---|:---|
| 前端/后端开发 | 理解需求细节、看实现方式 |
| 业务人员 | 验证需求是否符合业务场景 |
| 领导 | 功能演示、效果展示 |

## 二、系统架构

### 两层结构

```
┌─────────────────────────────────────┐
│  工具层：产品管理系统                 │
│  - 管理 Epic/Feature/Story          │
│  - 存储 PRD、本体论、模板、SOP       │
│  - Neo4j 图数据库存储产品知识         │
│  - AI 辅助需求拆解                   │
└─────────────────────────────────────┘
                    ↑ 指导
                    ↓ 补充
┌─────────────────────────────────────┐
│  产品层：数字社区（Demo 实现）        │
│  - 六大产品域的实际功能              │
│  - PRD 的具体实现案例                │
│  - 页面内嵌 PRD 文档链接（模式A）    │
└─────────────────────────────────────┘
```

### PRD 与数字社区的关系

| 方向 | 作用 |
|:---|:---|
| PRD → 数字社区 | 需求文档指导开发实现 |
| 数字社区 → PRD | Demo 实现补充 PRD 细节 |

### 集成模式：模式A（轻量集成）
页面内嵌 PRD 文档链接，不是深度耦合。开发可在数字社区页面快速跳转到对应 PRD 文档。
