## 1. 概述

本文档定义文档仓库中**本地文档 ↔ Neo4j ↔ 飞书** 三层链接的规范格式。

目标是实现：
- 文档与图谱节点双向可溯源
- 文档与飞书资源双向可跳转
- Epic/Feature/Story 与对应产品文档无缝关联

---

## 2. 核心概念

```
本地文档 ──Neo4j URI──▶ Epic/Feature/Story (图谱节点)
    │                          ▲
    └──Feishu Wiki/Doc URL──────┘
```

| 链接方向 | 作用 |
|----------|------|
| 文档 → Neo4j | 点链接查图谱血缘、状态 |
| Neo4j → 文档 | 查Epic时一键打开对应PRD |
| 文档 → 飞书 | 直接跳转飞书协作 |
| 飞书 → 文档 | 飞书Wiki引用本地文档路径 |

---

## 3. Frontmatter 元数据规范

每个产品文档头部必须包含以下元数据块：

```yaml
---
# Neo4j 关联（必填，标识文档对应的图谱节点）
neo4j:
  epic: "Epic:DMT:EPIC-DMT_BUSINESS_CONCEPT"   # 必填，对应Epic URI
  features:                                     # 选填，Feature URI列表
    - "Feature:DMT:FEAT-DMT-BC-DOMAIN"
    - "Feature:DMT:FEAT-DMT-BC-ENTITY"
  stories:                                      # 选填，Story ID列表（不含前缀）
    - "BC-DOMAIN-001"
    - "BC-DOMAIN-002"

# 飞书关联（选填）
feishu:
  wiki: "V8KEfpg1vlkCZld"                       # 知识库节点token
  doc: "https://example.feishu.cn/docx/xxx"      # 文档直链
  bitable: "tblxxx"                             # 多维表格ID

# 文档基本信息
doc:
  title: "业务概念管理PRD"                       # 中文标题
  version: "v1.0"                               # 当前版本
  status: "draft"                                # draft/review/approved/archived
  type: "PRD"                                   # PRD/需求/技术方案/操作手册
  productDomain: "PD-DMT"                       # 产品域代码
  epicKey: "EPIC-DMT_BUSINESS_CONCEPT"          # Epic简化key
  author: "Tony Stark"
  createdAt: "2026-04-29"
  updatedAt: "2026-04-29"
---

# 正文...
```

## 4. 文档内链接格式

### 4.1 链接 Neo4j 节点（使用 URI 格式）

```markdown
## 关联Epic

- Epic: Epic:DMT:EPIC-DMT_BUSINESS_CONCEPT
- Feature: Feature:DMT:FEAT-DMT-BC-DOMAIN
- Story: Story:DMT:BC-DOMAIN-001
```

### 4.2 链接本地其他文档（使用相对路径 + wikilink）

```markdown
## 关联文档

- 业务需求：[[../业务需求入口/2026-04-20-需求-业务概念管理.md]]
- 技术方案：[[../技术方案/2026-04-22-设计-业务概念数据模型.md]]
- 操作手册：[[../产品操作手册/2026-04-25-手册-业务域配置.md]]
```

### 4.3 链接飞书资源

```markdown
## 飞书协作

- 飞书Wiki：https://mcn2qsv100fk.feishu.cn/wiki/wiki/V8KEfpg1vlkCZld
- 飞书文档：https://mcn2qsv100fk.feishu.cn/docx/Bxxx
- 多维表格: https://mcn2qsv100fk.feishu.cn/base/Bxxx
```

### 4.4 Obsidian 风格双向链接（可选）

```markdown
- 关联Epic: [[Epic:DMT:EPIC-DMT_BUSINESS_CONCEPT]]
- 关联Feature: [[Feature:DMT:FEAT-DMT-BC-DOMAIN]]
- 相关文档: [[2026-04-20-需求-业务概念管理]]
```

## 5. URI 命名规范（与 Neo4j 一致）

### 5.1 Epic URI
```
格式: Epic:{产品域}:{EpicKey}
示例: Epic:DMT:EPIC-DMT_BUSINESS_CONCEPT
```

### 5.2 Feature URI
```
格式: Feature:{产品域}:{FeatureKey}
示例: Feature:DMT:FEAT-DMT-BC-DOMAIN
```

### 5.3 Story URI
```
格式: Story:{产品域}:{StoryKey}
示例: Story:DMT:BC-DOMAIN-001
```

### 5.4 ProductDomain URI
```
格式: ProductDomain:PD-{域代码}
示例: ProductDomain:PD-DMT
```

## 6. 目录结构与链接约定

```
数字社区项目/
└── {产品域}/
    └── {Epic名称}/              ← Epic粒度根目录
        ├── 业务需求入口/
        │   └── 2026-MM-DD-需求-{描述}.md
        ├── 需求拆解结果/
        │   └── 2026-MM-DD-拆解-{Epic名}.md
        ├── 产品PRD/
        │   └── 2026-MM-DD-PRD-{Epic名}.md    ← 主PRD文档
        ├── 产品操作手册/
        │   └── 2026-MM-DD-手册-{功能}.md
        └── 技术方案/
            └── 2026-MM-DD-设计-{模块}.md
```

**同级文档互相引用**：使用 `[[../同级目录/文件名]]`

**Epic级文档引用Feature/Story**：直接用 URI
