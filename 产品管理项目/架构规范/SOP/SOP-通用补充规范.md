## 1. 异常处理规范

### 1.1 异常分类

| 异常等级 | 标识 | 定义 | 处理策略 |
|:---:|:---:|:---|:---|
| **E1-阻断** | 🔴 | 步骤无法继续，缺核心输入 | 立即暂停，追问明确，记录 pending |
| **E2-降级** | 🟡 | 有替代方案，可继续但能力下降 | 使用降级方案，记录 warning |
| **E3-警告** | 🟢 | 不影响结果，但需记录 | 记录 log，继续执行 |

### 1.2 异常处理流程

```
发现异常
    │
    ├── E1-阻断 ──→ 暂停步骤，记录 pending_reason
    │               追问获取解决方案
    │               收到解决信号后 resume
    │
    ├── E2-降级 ──→ 记录 warning
    │               执行降级方案
    │               继续下一步
    │
    └── E3-警告 ──→ 记录 log
                    继续执行
```

### 1.3 每步必填的异常预定义

每个 SOP 步骤必须预定义以下异常：

| 步骤 | E1-阻断 | E2-降级 | E3-警告 |
|:---|:---|:---|:---|
| Step 1: xxx | 缺 xx 输入 | xx 字段为空 | xx 格式不标准 |
| Step 2: xxx | xx 文件不存在 | xx 模板版本旧 | xx 链接失效 |
| ... | | | |

### 1.4 异常记录格式

```json
{
  "step": "Step 3: 需求补充",
  "exception_level": "E1",
  "exception_type": "INPUT_MISSING",
  "field": "验收标准",
  "detail": "用户未提供验收标准",
  "pending_reason": "等待用户提供",
  "timestamp": "2026-05-13T09:35:00+08:00",
  "status": "PENDING"
}
```

## 2. 状态追踪规范

### 2.1 步骤状态定义

每个步骤必须记录以下状态：

| 状态 | 标识 | 定义 |
|:---:|:---:|:---|
| **pending** | ⏳ | 等待执行，前置条件未满足 |
| **running** | 🔄 | 执行中 |
| **done** | ✅ | 完成，输出已产出 |
| **failed** | ❌ | 失败，已记录异常 |
| **skipped** | ⏭️ | 跳过（不适用此场景） |

### 2.2 状态流转

```
⏳ pending
    │
    ▼ [触发条件满足]
🔄 running
    │
    ├─── ✅ done（成功）
    │
    ├─── ❌ failed（E1-阻断未解决）
    │
    └─── ⏭️ skipped（不适用）
```

### 2.3 状态记录模板

```json
{
  "sop_id": "SOP-S3",
  "execution_id": "EXEC-20260513-001",
  "steps": {
    "step_1": {
      "name": "需求接收",
      "status": "done",
      "output": "REQ-20260513-001",
      "timestamp": "2026-05-13T09:35:00+08:00"
    },
    "step_2": {
      "name": "需求理解",
      "status": "pending",
      "pending_reason": "等待Step1输出",
      "timestamp": null
    },
    "step_3": {
      "name": "需求补充",
      "status": "failed",
      "exception": {
        "level": "E1",
        "field": "验收标准",
        "reason": "用户未提供"
      },
      "timestamp": "2026-05-13T09:40:00+08:00"
    }
  }
}
```

```markdown

| 步骤 | E1-阻断 | E2-降级 | E3-警告 |
|:---|:---|:---|:---|
| Step 1 | xxx | xxx | xxx |
| Step 2 | xxx | xxx | xxx |

## Y. 状态流转图

```
Step1[✅] → Step2[🔄] → Step3[⏳]
              ↓
           [E1阻断] → 追问 → resume
```

## Z. 执行记录

| 执行ID | 日期 | 执行人 | 步骤状态 | 异常 | 备注 |
|:---|:---:|:---|:---|:---|:---|
| EXEC-xxx | 2026-05-13 | Tony | 3/5 done | 1个E1 | pending: 验收标准 |
```
