## 4. 处理流程

### 步骤 1: Epic 交付（IF-001）

**操作**：
1. Tony 准备 EPIC 交付包
2. 更新 Epic 状态为 `PENDING`
3. 发送 IF-001 给钟离

**交付内容**：
| 内容 | 说明 | 负责人 |
|:---|:---|:---:|
| EPIC 文档 | 含逻辑架构图（mermaid flowchart） | Tony |
| PRD 文档 | v5.0 审核通过版 | Tony |
| Spec 文档 | 技术方案 | Tony |
| 任务列表 | FP 拆解结果 | Tony |

**逻辑架构图要求**：
- 使用 mermaid flowchart 描述业务流程
- 标注业务域之间的数据流向
- 不涉及技术实现和系统边界

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | PRD 未审核通过 | 暂停，报告"PRD未通过审核"，等待SOP-S5完成 |
| **E1** | 缺少逻辑架构图 | 暂停，报告缺少逻辑架构图，需Tony补充 |
| E2 | 交付内容不完整（缺1-2项） | 降级：标注缺失项，继续交付，记录warning |
| E3 | 交付包文件名不规范 | 记录warning，自动重命名或标注需确认 |

---

### 步骤 2: 技术评估（钟离执行）

**前置条件**：IF-001 已接收

**操作**：
1. 钟离接收 EPIC
2. 技术可行性评估
3. 补充物理架构图（系统模块图）
4. 工时评估
5. 返回 IF-002

**物理架构图要求**：
- 使用 mermaid flowchart 描述系统模块
- 标注前端页面/组件、后端服务分层（API/Service/DAL）
- 描述数据库、缓存、消息队列等存储组件
- 描述系统间调用关系和 API 接口

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 技术不可行（REJECTED） | 暂停，收集钟离反馈，触发需求变更流程（SOP-S8） |
| **E2** | 工时超预期（NEED_REVISION） | 降级：记录工时差异，协商调整里程碑 |
| E2 | 物理架构图缺失 | 降级：标注待补充，继续其他评估，记录warning |
| E3 | 评估超时（>3天） | 记录warning，发送催评估提醒 |

---

### 步骤 3: 评审与确认

**输入**：IF-002（可行性报告）

**前置条件**：步骤2完成

**操作**：
1. Tony 审核可行性报告
2. 确认或要求修订
3. 通知钟离开始开发

**决策分支**：

| IF-002状态 | 操作 |
|:---|:---|
| APPROVED | 进入步骤4 |
| NEED_REVISION | 返回钟离修订，修订后重新提交 |
| REJECTED | 终止Epic，触发需求变更（SOP-S8） |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| E1 | PM审核不通过 | 暂停，收集审核意见，返回步骤2修订 |
| **E2** | 审核超时（>24h） | 降级：发送催审提醒，24h后未回复则标注"待确认"继续 |
| E3 | IF-002状态不明确 | 记录warning，追问确认状态 |

---

### 步骤 4: 开发阶段

**前置条件**：步骤3完成（APPROVED）

**操作**：
1. 钟离启动开发
2. 更新 Epic 状态为 `IN_PROGRESS`
3. Feature/Story 状态更新
4. Git 分支创建

**Git 工作流**：

```bash
# 创建开发分支
git checkout -b feature/EPIC-XX-XXX

# 提交代码
git add .
git commit -m "feat: EPIC-XX-XXX {description}"

# 创建 MR
git push -u origin feature/EPIC-XX-XXX
```

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| E1 | Git分支冲突 | 暂停，报告冲突，需手动解决后继续 |
| **E2** | 开发进度延期（>3天） | 降级：记录延期，触发风险预警（SOP-S12） |
| E3 | 代码规范检查失败 | 记录warning，通知钟离修复 |

---

### 步骤 5: Story 验收（IF-003）

**前置条件**：钟离完成Story开发

**操作**：
1. 钟离提交 Story 完成
2. Tony 执行 4 项验收
3. 返回 IF-003 验收结果

**4项验收标准**：

| 验收类型 | 检查内容 |
|:---|:---|
| 功能验收 | 功能是否完整、实现正确 |
| 操作验收 | 操作流程是否符合预期 |
| 数据验收 | 数据是否准确、计算正确 |
| 交互验收 | 界面交互是否友好 |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 验收不通过（REJECT） | 暂停，收集不通过原因，返回钟离修复 |
| E2 | 部分验收通过（PARTIAL） | 降级：记录未通过项，继续其他验收，汇总待修复清单 |
| **E2** | 验收超时（Story提交后>48h未验收） | 降级：发送催验收提醒，超时72h则自动标注"待验收" |
| E3 | 验收标准描述模糊 | 记录warning，补充标准描述或标注需明确 |

---

### 步骤 6: Epic 完成（IF-004）

**前置条件**：所有 Story 验收通过（IF-003 = ACCEPT）

**操作**：
1. 钟离确认完成
2. 更新 Epic 状态为 `COMPLETED`
3. 通知相关方

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| E1 | 仍有 Story 未验收 | 暂停，报告未验收清单，拒绝完成确认 |
| E2 | 完成确认延迟（>24h） | 记录warning，发送催确认提醒 |
| E3 | 文档未同步到飞书 | 记录warning，触发飞书同步（SOP-S7） |

## 5. 状态流转

```
步骤1[Epic交付]
    │
    ├── ✅ done → 步骤2（等待钟离评估）
    ├── ❌ failed（PRD未审核/缺逻辑架构图）→ [暂停，修复后resume]
    └── ⚠️ done（交付内容不完整）→ 降级继续 → 步骤2

步骤2[技术评估]
    │
    ├── ✅ done（APPROVED）→ 步骤3
    ├── ❌ failed（REJECTED）→ [暂停，触发需求变更SOP-S8]
    └── ⚠️ done（NEED_REVISION）→ [返回修订，修订后resume]

步骤3[评审确认]
    │
    ├── ✅ done（APPROVED）→ 步骤4
    ├── ❌ failed（审核不通过）→ [返回步骤2修订]
    └── ⏳ pending（审核超时）→ [催审，24h后降级继续]

步骤4[开发阶段]
    │
    ├── ✅ done → 步骤5（等待Story完成）
    └── ⚠️ done（进度延期）→ [继续，触发风险预警]

步骤5[Story验收]
    │
    ├── ✅ done（全部ACCEPT）→ 步骤6
    ├── ⚠️ done（部分PARTIAL）→ [汇总待修复，继续]
    └── ❌ failed（有REJECT）→ [暂停，返回修复]

步骤6[Epic完成]
    │
    └── ✅ done → [SOP完成]
```

## 6. Epic 状态流转

```
DRAFT → PENDING → IN_PROGRESS → PENDING_REVIEW → COMPLETED
         ↓              ↓
    NEED_REVISION    BLOCKED
         ↓
    PENDING（重新提交）
```

## 7. 验收检查清单

**交付前**：
- [ ] EPIC 文档完整（含逻辑架构图）
- [ ] PRD 文档完整（审核通过）
- [ ] Spec 文档完整
- [ ] 任务列表完整
- [ ] 逻辑架构图已绘制

**技术评估后**：
- [ ] 物理架构图已补充（钟离负责）
- [ ] 可行性报告已返回

**开发中**：
- [ ] 技术可行性已评估
- [ ] 开发进度正常（或已触发预警）
- [ ] 代码符合规范

**验收时**：
- [ ] 功能验收通过
- [ ] 操作验收通过
- [ ] 数据验收通过
- [ ] 交互验收通过
- [ ] 代码已合并

**完成后**：
- [ ] Epic 状态为 COMPLETED
- [ ] 所有文档已更新
- [ ] 飞书状态已同步
