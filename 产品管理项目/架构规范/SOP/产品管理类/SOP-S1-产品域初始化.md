## 1. 概述

### 1.1 目标

新建产品域时，初始化完整的产品管理框架，包括文档、数据库、飞书表格。

### 1.2 触发时机

| 触发类型 | 说明 | 优先级 |
|:---|:---|:---:|
| 新建产品域 | 业务线扩展新产品域 | P0 |
| 产品线扩展 | 现有产品新增子域 | P1 |

**触发信号**：收到产品域创建需求（飞书消息/文档）

### 1.3 输入

| 输入项 | 必填 | 说明 |
|:---|:---:|:---|
| 产品域 ID | ✅ | 格式：PD-{2位字母} |
| 产品域名称 | ✅ | 中文名称 |
| 英文名 | ✅ | 英文标识 |
| 产品定位 | ✅ | 一句话定位 |
| 核心价值 | ✅ | 核心价值主张 |
| 业务范围描述 | ✅ | 业务边界 |
| 团队成员 | ⚠️ | 可后补 |
| 目录结构规范 | ❌ | 使用标准规范 |

### 1.4 输出

| 输出项 | 状态 | 说明 |
|:---|:---:|:---|
| 产品域说明文档 | ⏳待产出 | v1.3，含逻辑+物理架构图 |
| Epic 说明文档列表 | ⏳待产出 | 每个Epic一个文档 |
| Neo4j 节点 | ⏳待产出 | ProductDomain + Epic |
| 飞书多维表格 | ⏳待产出 | 含标准字段配置 |

## 2. 处理流程

### 步骤 1: 创建目录结构

**操作**：创建标准产品域目录

```
产品管理项目/
└── PRD/
    └── {产品域名称}/
        ├── 01-产品域说明.md
        ├── 02-EPIC文档/
        │   ├── 01-EPIC-XXX.md
        │   └── 02-EPIC-YYY.md
        └── 03-Feature文档/
            ├── 01-Feature-XXX.md
            └── 02-Feature-YYY.md
```

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| E2 | 目录已存在 | 询问覆盖还是追加，确认后执行 |
| E3 | 权限不足 | 记录警告，尝试 sudo 或报告 |

### 步骤 3: 创建 Epic 说明文档

**模板**：`架构规范/模板/03-EPIC说明文档.md`（v1.1）

**每个 Epic 需要创建**：
- Epic 说明文档（含逻辑架构图）
- 关联的 Feature 说明文档

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| E1 | Epic ID 格式错误 | 暂停，追问正确ID格式 |
| E2 | Epic 数量超范围（<1或>10） | 记录警告，继续，标注异常数量 |
| E3 | 目录创建失败 | 记录日志，继续创建其他目录 |

---

### 步骤 4: 同步到 Neo4j

**Skill 调用**：`product-breakdown`

**前置条件**：步骤2、3已完成

**操作**：

```bash
# 创建 ProductDomain 节点
CREATE (pd:ProductDomain {
  id: "PD-XX",
  name: "{产品域名称}",
  description: "{描述}",
  created_at: datetime()
})

# 创建 Epic 节点
CREATE (e:Epic {
  id: "EPIC-XX-XXX",
  name: "{Epic名称}",
  product_domain: "PD-XX",
  status: "DRAFT",
  created_at: datetime()
})

# 创建 BELONGS_TO 关系
MATCH (pd:ProductDomain {id: "PD-XX"})
MATCH (e:Epic {id: "EPIC-XX-XXX"})
CREATE (e)-[:BELONGS_TO]->(pd)
```

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | Neo4j 连接失败 | 暂停，尝试3次重连（间隔10s），仍失败则记录pending |
| **E1** | 节点ID已存在 | 暂停，追问覆盖/跳过/改名 |
| E2 | 部分Epic创建失败 | 记录warning，继续创建其他的，记录失败列表 |
| E3 | 关系创建失败 | 记录日志，Node已创建，告知需手动补充关系 |

---

### 步骤 5: 初始化飞书多维表格

**Skill 调用**：`feishu-sync`

**前置条件**：步骤4已完成

**操作**：

1. 创建飞书多维表格
2. 配置字段：
   - Epic ID
   - Feature ID
   - Story ID
   - FP ID
   - 状态
   - 负责人
   - 优先级
   - 完成度

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 飞书API认证失败 | 暂停，报告认证问题，需手动解决 |
| E2 | 部分字段创建失败 | 记录warning，使用简化字段列表继续 |
| E3 | 表格创建超时 | 重试1次，仍超时报warning告知手动创建 |

## 3. 状态流转

```
步骤1[创建目录结构]
    │
    ├── ✅ done → 步骤2
    └── ❌ failed → [E1阻断] → 追问解决 → resume

步骤2[创建产品域说明文档]
    │
    ├── ✅ done → 步骤3
    ├── ⏭️ skipped（模板不存在，E1）→ [SOP中止，报告问题]
    └── ❌ failed → 降级处理，继续（E2）

步骤3[创建Epic说明文档]
    │
    ├── ✅ done → 步骤4
    └── ❌ failed → 记录warning，继续

步骤4[同步Neo4j]
    │
    ├── ✅ done → 步骤5
    ├── ⏳ pending（连接失败，E1）→ 等待重连或手动解决
    └── ❌ failed → 部分成功，继续

步骤5[初始化飞书]
    │
    ├── ✅ done → [SOP完成]
    └── ❌ failed → [部分完成，报告需手动处理项]
```
