## 1. 概述

### 1.1 目标

生成符合 v5.0 规范的 PRD，用于指导开发

### 1.2 触发时机

| 触发类型 | 说明 | 优先级 |
|:---|:---|:---:|
| S4 需求拆解完成 | SOP-S4 步骤5产出 | P0 |
| Epic/Feature/Story 确认 | PM 确认拆解结果 | P0 |

**触发信号**：需求拆解结果已确认 / 收到 PRD 生成指令

### 1.3 输入

| 输入项 | 必填 | 说明 |
|:---|:---:|:---|
| 需求理解报告 | ✅ | 9项信息 |
| Epic/Feature/Story/FP 列表 | ✅ | SOP-S4 输出 |
| Neo4j 数据 | ✅ | 可选，辅助校验 |

### 1.4 输出

| 输出项 | 状态 | 说明 |
|:---|:---:|:---|
| PRD v5.0 文档 | ⏳待产出 | 10章节完整结构 |
| Spec 文档 | ⏳待产出 | 技术方案 |
| 任务列表 | ⏳待产出 | 可导入Jira/TAPD |

## 2. 处理流程

### 步骤 1: PRD 生成

**Skill 调用**：`prd-generation`

**前置条件**：SOP-S4 完成

**输入**：`requirement-breakdown` 输出的结构化需求

**流程**：

```
S1: 接收与解析
    └─→ 接收需求 JSON

S2: Feature 解析
    └─→ 提取 Feature 列表

S3: FP 拆解
    └─→ 将 Feature 拆解为 FP

S4: 菜单映射
    └─→ 关联 FP 到菜单路径

S5: 审批流接入
    └─→ 标注审批流节点

S6: 输出 PRD
    └─→ 生成 PRD 文档
```

**PRD v5.0 结构**：

| # | 章节 | 状态 | 说明 |
|:---:|:---|:---:|:---|
| 一 | 元数据 | ⏳ | 产品域、Epic、版本、审核人 |
| 二 | 变更日志 | ⏳ | 版本变更记录 |
| 三 | 需求背景 | ⏳ | 目标、痛点、挑战 |
| 四 | 需求范围 | ⏳ | 功能范围、不在范围内 |
| 五 | 功能详情 | ⏳ | Feature + Story |
| 六 | Story与FP关联 | ⏳ | 按 Story 拆分 FP |
| 七 | FP清单汇总 | ⏳ | 完整 FP 列表 |
| 八 | 菜单映射表 | ⏳ | 路由路径映射 |
| 九 | 审批流接入 | ⏳ | 审批节点、角色 |
| 十 | 版本历史 | ⏳ | 版本变更记录 |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 需求 JSON 格式错误 | 暂停，报告JSON解析错误，定位错误位置 |
| **E1** | Feature 数量为0 | 暂停，报告"缺少Feature数据"，返回SOP-S4 |
| E2 | 部分章节填充失败 | 降级：使用占位符，标注"待补充"，继续 |
| E3 | 菜单映射缺失 | 记录warning，标注"待映射"，继续 |

---

### 步骤 2: PRD 审核

**输入**：PRD v5.0 文档

**前置条件**：步骤1完成

**操作**：
1. PM 审核 PRD 内容
2. 确认 Feature/Story/FP 完整性
3. 确认验收标准
4. 确认菜单映射
5. 签字确认

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| E1 | PM 审核不通过 | 暂停，收集审核意见，返回步骤1修改 |
| **E2** | PM 超时未审核（>48h） | 降级：发送催审提醒，48h后未回复则标注"待确认"继续 |
| E3 | 部分章节为占位符 | 记录warning，继续，标注待补充项 |

---

### 步骤 3: Spec 生成

**Skill 调用**：`spec-driven`

**前置条件**：步骤2完成（PRD审核通过）

**目标**：将 PRD 转化为开发可执行的 Spec

**Spec 内容**：

| 章节 | 状态 | 说明 |
|:---|:---:|:---|
| 技术方案 | ⏳ | 技术选型、架构设计 |
| 接口定义 | ⏳ | API 接口、参数、返回值 |
| 数据模型 | ⏳ | 数据库表、字段定义 |
| 任务拆解 | ⏳ | 按 FP 拆解为开发任务 |
| 排期 | ⏳ | 工时评估、里程碑 |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | PRD 未通过审核 | 暂停，返回步骤2，等审核通过 |
| E2 | 技术选型无法确定 | 降级：标注"待技术评审"，继续其他章节 |
| E3 | 接口定义不完整 | 记录warning，补充基本定义，标注待完善 |

---

### 步骤 4: 任务规划

**Skill 调用**：`task-planning`

**前置条件**：步骤3完成

**操作**：
1. 将 FP 拆解为开发任务
2. 分配负责人
3. 确定里程碑
4. 创建任务关联

**输出**：任务列表（可导入 Jira/TAPD）

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | Spec 文档不完整 | 暂停，报告缺失章节，返回步骤3补充 |
| E2 | 负责人无法确定 | 降级：标记"待分配"，继续其他任务 |
| E3 | 里程碑冲突 | 记录warning，尝试调整，标注需确认 |

## 3. 状态流转

```
步骤1[PRD生成]
    │
    ├── ✅ done（10章节完整）→ 步骤2
    ├── ❌ failed（JSON错误/无Feature）→ [报告问题，暂停]
    └── ⚠️ done（部分章节待补充）→ 降级继续 → 步骤2

步骤2[PRD审核]
    │
    ├── ✅ done（PM通过）→ 步骤3
    ├── ❌ failed（PM不通过）→ [收集意见，返回步骤1]
    └── ⏳ pending（PM超时）→ [催审提醒，48h后降级继续]

步骤3[Spec生成]
    │
    ├── ✅ done → 步骤4
    ├── ❌ failed（PRD未审核）→ [暂停，等审核]
    └── ⚠️ done（部分章节待完善）→ 降级继续 → 步骤4

步骤4[任务规划]
    │
    ├── ✅ done → [SOP完成]
    ├── ❌ failed（Spec不完整）→ [报告问题，返回步骤3]
    └── ⚠️ done（部分待分配）→ 降级继续 → [SOP完成]
```
