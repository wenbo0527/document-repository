## 1. 概述

### 1.1 目标

日常维护文档、Neo4j、飞书的同步一致性

### 1.2 触发时机

| 触发类型 | 说明 | 优先级 | 触发信号 |
|:---|:---|:---:|:---|
| 定时触发 | 每周一9:00 | P1 | 定时任务 |
| 手动触发 | 发现数据不一致时 | P0 | 人工执行 |
| 事件触发 | PRD定稿/Epic状态变更 | P1 | 事件驱动 |
| **EPIC重建触发** | **健康检查发现问题/文档缺失/Neo4j不一致** | **P0** | **SOP-S2子流程** |

> **📌 注意**：SOP-S2（产品域EPIC重建）已降级为本SOP的子流程，当文档/数据出现严重不一致时触发

### 1.3 输入

| 输入项 | 必填 | 说明 |
|:---|:---:|:---|
| 上次维护记录 | ⚠️ | 可选，用于对比 |
| 健康检查报告 | ⚠️ | 手动触发时必填 |
| 维护范围 | ✅ | 全量/指定产品域 |
| EPIC重建清单 | ⚠️ | 子流程触发时必填 |

### 1.4 输出

| 输出项 | 状态 | 说明 |
|:---|:---:|:---|
| 维护报告 | ⏳待产出 | 健康检查结果+问题处理 |
| 问题修复记录 | ⏳待产出 | 各类问题的处理结果 |
| 更新后的文档/数据 | ⏳待产出 | 同步完成的确认 |

## 2. 处理流程

### 步骤 1: 健康检查

**Skill 调用**：`health-check`

**前置条件**：无

**执行频率**：每周一次（定时）/ 按需（手动）

**检查项**：

| 检查项 | 检查内容 | 工具 |
|:---|:---|:---|
| Neo4j 检查 | 节点数量、关系完整性 | `neo4j_check.py` |
| 飞书检查 | 文档同步状态 | `feishu_check.py` |
| Wiki 检查 | 知识库完整性 | `wiki_check.py` |
| **模板检查** | **模板版本（01-09）** | **`template_check.py`** |
| **EPIC重建检查** | **文档缺失/数据不一致** | **触发SOP-S2子流程** |

**操作**：

```bash
# 执行健康检查
python3 health_check.py --report

# 指定产品域
python3 health_check.py --domain PD-XX --report

# 输出检查报告
# /tmp/health_check_report_{date}.json
```

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| E1 | 健康检查脚本不存在 | 暂停，报告缺少脚本，需手动补充 |
| **E2** | 检查超时（>120s） | 降级为抽样检查（抽3个产品域），记录warning |
| E3 | 部分检查项工具缺失 | 记录warning，跳过该检查项，继续其他 |

**EPIC重建检查项**（发现以下问题时触发子流程）：

| 检查项 | 问题定义 | 触发子流程条件 |
|:---|:---|:---|
| 文档缺失 | 产品域/EPIC/Feature文档不存在 | 任意1个即触发 |
| Neo4j不一致 | 节点数量与文档不符 | 任意1个即触发 |
| 版本过期 | 文档版本与模板版本不符 | >3个触发 |
| 关系缺失 | CONTAINS/BELONGS_TO关系缺失 | 任意1个即触发 |

---

### 步骤 2: 问题修复

**输入**：健康检查报告（问题清单）

**前置条件**：步骤1完成

**问题分类处理**：

| 问题类型 | 定义 | 处理方式 | Skill |
|:---|:---|:---|:---|
| 文档缺失 | 某类文档不存在 | 创建/补齐 | `requirement-breakdown` |
| 数据不一致 | Neo4j 与文档不符 | 修复数据 | `neo4j-product-domain-repair` |
| 版本过期 | 模板/文档版本过旧 | 更新版本 | 手动 |
| 关系缺失 | 节点关系不完整 | 补充关系 | `neo4j-product-domain-repair` |

**操作流程**：
1. 确认问题清单
2. 按优先级修复（P0>P1>P2）
3. 验证修复结果

> **📌 SOP-S2 子流程**：当问题类型为"文档缺失"或"Neo4j不一致"且数量较多时，执行EPIC重建子流程

**EPIC重建子流程**（步骤2.1-2.5）：

```
步骤2.1: 诊断问题类型
    │
    ├── 文档缺失 → 步骤2.2
    ├── Neo4j不一致 → 步骤2.3
    └── 关系缺失 → 步骤2.4

步骤2.2: 补齐文档
    ├── 产品域说明文档缺失 → 使用模板创建
    ├── EPIC说明文档缺失 → 遍历Neo4j，按模板创建
    ├── Feature说明文档缺失 → 遍历Neo4j，按模板创建
    └── PRD文档缺失 → 使用PRD模板创建

步骤2.3: 修复Neo4j数据
    ├── 缺失节点 → 创建
    ├── 错误关系 → 修复
    ├── id重复 → 去重
    └── NULL id → 补全

步骤2.4: 补充关系
    ├── 补充BELONGS_TO关系
    └── 补充CONTAINS关系

步骤2.5: 同步飞书
    └── 同步修复结果到飞书
```

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 问题数量>100 | 暂停，拆分为多个子任务，分批处理 |
| **E1** | EPIC重建子流程失败 | 暂停，报告失败节点，继续其他修复 |
| E2 | 部分问题修复失败 | 记录warning，继续修复其他的，汇总失败列表 |
| E3 | 修复后验证不一致 | 记录warning，标记需二次校验 |

### 步骤 3: Wiki 维护

**Skill 调用**：`wiki-maintenance`

**前置条件**：步骤2完成（或与步骤2并行）

**执行频率**：每周一次

**检查项**：

| 检查项 | 说明 |
|:---|:---|
| 文档完整性 | 专题文档是否齐全 |
| 双向链接 | 链接是否有效 |
| 内容时效性 | 是否过期 |
| 格式规范 |是否符合规范 |

**维护操作**：
1. 创建/更新专题文档
2. 修复失效链接
3. 更新过期内容
4. 补充双向链接

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| E1 | Wiki 目录无写入权限 | 暂停，报告权限问题，需手动解决 |
| E2 | 失效链接数量>50 | 降级：优先修复内链，外链标注待处理 |
| E3 | 内容过期但无更新权限 | 记录warning，标注"待更新"，通知负责人 |

---

### 步骤 4: 飞书同步

**Skill 调用**：`feishu-sync`

**触发条件**：
- PRD 定稿后
- Epic 状态变更
- 每周定期同步

**前置条件**：无（可独立执行）

**同步内容**：

| 内容 | 同步方式 | 说明 |
|:---|:---|:---|
| PRD 文档 | 手动同步 | 需要确认版本 |
| 状态变更 | 自动同步 | Neo4j变更触发 |
| 里程碑 | 自动同步 | 定时同步 |
| 周报 | 自动同步 | 定时生成发送 |

**操作**：

```bash
# 同步 PRD 到飞书
python3 feishu_sync.py --type prd --id {doc_id}

# 同步状态到飞书
python3 feishu_sync.py --type status --domain {domain}
```

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 飞书API认证失败 | 暂停，报告认证问题，需手动解决 |
| E2 | 部分内容同步失败 | 记录warning，继续同步，记录失败列表 |
| E3 | 同步超时 | 重试1次，仍超时报warning告知手动同步 |

## 3. 状态流转

```
步骤1[健康检查]
    │
    ├── ✅ done（发现问题）→ 步骤2
    │   └── EPIC重建触发 → 执行子流程2.1-2.5
    ├── ✅ done（无问题）→ 步骤4（轻量执行）
    └── ❌ failed（脚本缺失）→ [SOP中止，报告问题]

步骤2[问题修复]
    │
    ├── ✅ done（全部修复）→ 步骤4
    ├── ⚠️ done（部分失败）→ 步骤4（记录warning）
    └── ❌ failed（问题过多>100）→ [暂停，拆分任务]

步骤3[Wiki维护]
    │
    ├── ✅ done → 步骤4（继续）
    └── ❌ failed（权限问题）→ [暂停，报告问题]

步骤4[飞书同步]
    │
    ├── ✅ done → [SOP完成]
    └── ⚠️ done（部分失败）→ [记录warning，继续]
```
