## 2. 早上流程（5-10min）

### 步骤 1: 健康检查

**执行命令**：

```bash
cd /Users/wenbo/Documents/project/product_managment/backend-python
python3 health_check.py
```

**必过项（全部通过才视为健康）**：

| # | 检查项 | 标准 | 未通过处理 |
|:---:|:---|:---|:---|
| 1 | 孤儿 Story | = 0 | 查询孤立 Story，补齐 BELONGS_TO 关系 |
| 2 | 孤儿 Feature | = 0 | 查询孤立 Feature，补齐关联 |
| 3 | Story 验收标准 | 非空 | 补充 acceptance_criteria |
| 4 | 中文 ID | = 0 | 检查 ID 命名规范，强制修复 |
| 5 | CONTAINS 关系 | 完整 | 补齐缺失关系 |

**健康检查输出格式**：

```json
{
  "date": "2026-04-25",
  "overall_status": "HEALTHY | WARNING | CRITICAL",
  "checks": [
    {"item": "孤儿 Story", "status": "PASS", "count": 0},
    {"item": "孤儿 Feature", "status": "PASS", "count": 0},
    {"item": "Story 验收标准", "status": "PASS", "count": 0},
    {"item": "中文 ID", "status": "PASS", "count": 0},
    {"item": "关系完整性", "status": "PASS", "count": 0}
  ],
  "issues": [],
  "action_required": []
}
```

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 健康检查脚本不存在 | 暂停，报告缺少脚本，需手动安装 |
| **E2** | Neo4j 连接失败 | 暂停，尝试3次重连，仍失败则标注"数据不可用" |
| E3 | 检查超时（>60s） | 记录warning，输出已完成的检查项，标注超时项 |

---

### 步骤 2: 预警检查

**前置条件**：步骤1完成

**检查项**：

| 预警级别 | 触发条件 | 通知方式 | 处理时效 |
|:---|:---|:---|:---|
| 🔴 红色 | 里程碑完成度 < 80%，剩余时间 < 20% | 立即通知 | 2h 内 |
| 🟠 橙色 | 里程碑完成度 < 70%，剩余时间 < 30% | 24h 内通知 | 当日处理 |
| 🟡 黄色 | 里程碑完成度 < 50%，剩余时间 > 50% | 周报中体现 | 3 日内 |

**风险预警（SOP-S12）**：

| 风险等级 | 监控频率 |
|:---|:---:|
| 高 | 每天 |
| 中 | 每周 |
| 低 | 每两周 |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 🔴红色预警触发 | 暂停，立即处理，2h内必须给出应对措施 |
| E2 | 数据不可用（步骤1失败） | 降级：基于上次检查结果判断，标注"数据延迟" |
| E3 | 预警计算缺少里程碑数据 | 记录warning，跳过里程碑预警，继续其他检查 |

---

### 步骤 3: 今日待办

**前置条件**：步骤2完成

**待办来源**：
- 昨日未完成任务
- 新分配的需求
- Epic 交付跟踪
- 风险应对任务

**输出**：今日待办清单（MUST / SHOULD / NICE）

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 昨日任务全部未完成 | 暂停，分析阻塞原因，记录到站会 |
| E2 | 新任务冲突（时间不够） | 降级：按优先级排序，调整到次日 |
| E3 | 待办来源数据缺失 | 记录warning，根据印象补全，标注"待确认" |

## 3. 傍晚流程（5min）

> **📌 注意**：步骤4-5原为独立SOP-S13.1（每日站会记录），现并入本SOP

### 步骤 4: 站会记录

**前置条件**：白天工作完成

**操作流程**：

```
Step 4.1: 打开模板
    │
    ├── 打开 /tmp/daily_standup_{date}.md
    └── 复制极简版模板

Step 4.2: 填写内容（2-3分钟）
    │
    ├── 今日完成（参考昨日计划 + Neo4j状态）
    ├── 进行中（参考开发进度）
    ├── 明日计划（参考Epic交付计划）
    └── 阻塞/风险（有则记录，无则写"无"）

Step 4.3: 保存并发送
    │
    ├── 保存到 /tmp/daily_standup_{date}.md
    ├── 如有阻塞问题 → 发送飞书通知给相关人
    └── 同步到周报素材
```

**快速符号**：

| 符号 | 含义 | 使用场景 |
|:---|:---|:---|
| ✅ | 完成 | 今日完成的事项 |
| 🚧 | 进行中 | 正在进行的工作 |
| 📅 | 计划 | 明日计划 |
| ⚠️ | 阻塞 | 有阻塞问题 |
| 🔔 | 风险 | 有风险需要关注 |
| ❌ | 延期 | 有任务延期 |

**极简版模板（推荐）**：

```
## YYYY-MM-DD 站会

✅ 今日完成: Epic-A / Feature-B
🚧 进行中: Feature-C (60%)
📅 明日计划: Feature-D
⚠️ 阻塞: 无 / [问题描述 → @xxx]
🔔 风险: 无 / [风险描述]

---
记录: {HH:mm}
```

**标准版模板**：

```markdown
# 站会记录 - {YYYY-MM-DD}

## 1. 今日完成
| 类型 | ID | 名称 | 状态 |
|:---|:---|:---|:---|
| Epic | EPIC-XXX | 名称 | ✅ 完成 |
| Feature | FEAT-XXX | 名称 | ✅ 完成 |
| Story | STORY-XXX | 名称 | ✅ 完成 |

## 2. 今日进行中
| 类型 | ID | 名称 | 进度 | 预计完成 |
|:---|:---|:---|:---:|:---|
| Feature | FEAT-XXX | 名称 | 60% | 明日 |

## 3. 明日计划
- [ ] Feature-D 开发
- [ ] Story-E 验收

## 4. 阻塞问题
| 问题 | 影响 | 处理人 | 截止时间 |
|:---|:---|:---|:---|
| 接口文档缺失 | 阻塞开发 | @xxx | 今日 |

## 5. 风险预警
| 风险 | 级别 | 应对措施 | 状态 |
|:---|:---|:---|:---|
| 第三方接口延期 | 中 | 已通知业务方 | 监控中 |

---
记录时间: {HH:mm}
记录人: Tony Stark
```

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 今日完成=0 且 进行中=0（全天无产出） | 暂停，分析原因，记录到"问题"字段，标注"需复盘" |
| E2 | Neo4j状态查询失败 | 降级：基于记忆填写，标注"待确认" |
| **E2** | 有阻塞但无法发送通知 | 立即升级给派蒙，口头通知，不能延误 |
| E3 | 内容超过5行 | 记录warning，坚持极简版，压缩到5行内 |

## 5. 状态流转

```
🌅 早上流程
├── 步骤1[健康检查]
│   ├── ✅ done（全部PASS）→ 步骤2
│   ├── ❌ failed（脚本不存在/Neo4j失败）→ [暂停，报告问题]
│   └── ⚠️ done（有WARN）→ 记录warning → 步骤2
│
├── 步骤2[预警检查]
│   ├── ✅ done（无预警）→ 步骤3
│   ├── ✅ done（有预警已处理）→ 步骤3
│   └── ❌ failed（红色预警+无法处理）→ [升级派蒙]
│
└── 步骤3[今日待办]
    └── ✅ done → [早上流程结束]

🌙 傍晚流程
├── 步骤4[站会记录]
│   ├── ✅ done → 步骤5
│   ├── ❌ failed（全天无产出）→ [记录原因，标注需复盘] → 步骤5
│   └── ⚠️ done（有阻塞已升级）→ 步骤5
│
└── 步骤5[周报素材积累]
    └── ✅ done → [傍晚流程结束]
```
