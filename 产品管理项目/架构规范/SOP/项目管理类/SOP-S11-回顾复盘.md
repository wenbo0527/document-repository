## 1. 概述

### 1.1 目标

项目/阶段结束后进行复盘，总结经验教训，持续改进

### 1.2 触发时机

- Epic 完成时
- 项目结束
- 里程碑达成
- 季度末

### 1.3 输入

- 项目数据
- 周报/月报
- 风险记录

### 1.4 输出

- 复盘报告
- 改进项清单
- 经验沉淀

---

## 2. 处理流程

### 步骤 1: 复盘准备

**操作**：
1. 确定复盘范围
2. 确定参与人员
3. 收集数据
4. 发送复盘议程

**复盘议程**：

```markdown
# 复盘会议 - {Epic/项目名称}

## 时间
{{datetime}}

## 参与人员
- {{participants}}

## 议程
1. 回顾目标（10min）
2. 评估结果（20min）
3. 分析原因（30min）
4. 总结经验（20min）
5. 制定改进（20min）
```

---

### 步骤 2: 复盘会议

**复盘维度**：

| 维度 | 问题 |
|:---|:---|
| 目标达成 | 是否达成目标？差距在哪？ |
| 进度管理 | 是否按计划完成？延期原因？ |
| 质量控制 | 质量是否达标？问题在哪？ |
| 团队协作 | 协作是否顺畅？ |
| 风险管理 | 风险应对是否有效？ |

**KPT 模型**：

| 类型 | 内容 |
|:---|:---|
| K（Keep）| 做得好的，继续保持 |
| P（Problem）| 做得不好的，需要改进 |
| T（Try）| 下次尝试的新方法 |

---

### 步骤 3: 问题归档

**问题分类**：

| 类型 | 说明 |
|:---|:---|
| 流程问题 | 流程不顺畅、需要优化 |
| 技术问题 | 技术方案问题 |
| 沟通问题 | 信息不对称、沟通不畅 |
| 资源问题 | 资源不足或分配不当 |

**问题记录表**：

| 问题ID | 问题描述 | 类型 | 责任方 | 改进措施 | 状态 |
|:---|:---|:---|:---|:---|:---|
| {{id}} | {{desc}} | {{type}} | {{owner}} | {{action}} | TODO |

---

### 步骤 4: 改进跟踪

**改进项管理**：

1. 确定改进优先级
2. 分配责任人
3. 设定完成时间
4. 下次复盘时检查

**改进优先级**：

| 优先级 | 说明 |
|:---|:---|
| P0 | 紧急改进，下个迭代必须解决 |
| P1 | 重要改进，2周内解决 |
| P2 | 一般改进，下月解决 |

---

### 步骤 5: 经验沉淀

**沉淀内容**：

| 类型 | 内容 |
|:---|:---|
| 最佳实践 | 做得好的方法论 |
| 教训总结 | 踩过的坑 |
| 工具模板 | 有效的工具和模板 |
| 检查清单 | 避免重复犯错 |
