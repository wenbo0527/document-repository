# SOP-S13.1: 每日站会记录

> **版本**: v1.0
> **日期**: 2026-04-25
> **作者**: Tony Stark
> **状态**: 正式发布

---

## 1. 概述

### 1.1 目标

轻量级每日站会记录，积累周报素材，同步项目状态。

### 1.2 触发时机

- 每日傍晚（约 17:00）
- 或每日早上（可选）

### 1.3 适用范围

- 快速记录项目状态
- 积累周报素材
- 记录阻塞问题

### 1.4 原则

**轻量优先**：站会记录不超过 5 分钟，拒绝完美主义文档。

---

## 2. 站会记录模板

### 2.1 极简版（推荐）

```
## YYYY-MM-DD 站会

✅ 今日完成: Epic-A / Feature-B
🚧 进行中: Feature-C (60%)
📅 明日计划: Feature-D
⚠️ 阻塞: 无 / [问题描述 → @xxx]
🔔 风险: 无 / [风险描述]

---
记录: {HH:mm}
```

### 2.2 标准版

```markdown
# 站会记录 - {YYYY-MM-DD}

## 1. 今日完成
| 类型 | ID | 名称 | 状态 |
|:---|:---|:---|:---|
| Epic | EPIC-XXX | 名称 | ✅ 完成 |
| Feature | FEAT-XXX | 名称 | ✅ 完成 |
| Story | STORY-XXX | 名称 | ✅ 完成 |

## 2. 今日进行中
| 类型 | ID | 名称 | 进度 | 预计完成 |
|:---|:---|:---|:---:|:---|
| Feature | FEAT-XXX | 名称 | 60% | 明日 |

## 3. 明日计划
- [ ] Feature-D 开发
- [ ] Story-E 验收

## 4. 阻塞问题
| 问题 | 影响 | 处理人 | 截止时间 |
|:---|:---|:---|:---|
| 接口文档缺失 | 阻塞开发 | @xxx | 今日 |

## 5. 风险预警
| 风险 | 级别 | 应对措施 | 状态 |
|:---|:---|:---|:---|
| 第三方接口延期 | 中 | 已通知业务方 | 监控中 |

---
记录时间: {HH:mm}
记录人: Tony Stark
```

### 2.3 升级版（有阻塞问题时使用）

```markdown
# 站会记录 - {YYYY-MM-DD} ⚠️

## 阻塞升级
### 问题描述
[具体描述]

### 影响范围
- Epic: EPIC-XXX
- Feature: FEAT-XXX
- 里程碑: M-XXX (明日)

### 已尝试的解决方案
1. ...
2. ...

### 需要支援
- 资源: 前端支援
- 决策: 是否接受延期

### 升级给
- @xxx（处理人）
- @yyy（抄送）

### 截止时间
YYYY-MM-DD HH:mm
```

## 3. 记录格式规范

### 3.1 快速符号

| 符号 | 含义 | 使用场景 |
|:---|:---|:---|
| ✅ | 完成 | 今日完成的事项 |
| 🚧 | 进行中 | 正在进行的工作 |
| 📅 | 计划 | 明日计划 |
| ⚠️ | 阻塞 | 有阻塞问题 |
| 🔔 | 风险 | 有风险需要关注 |
| ❌ | 延期 | 有任务延期 |

### 3.2 进度格式

```
Feature: FEAT-XXX (60%)
Story: STORY-XXX (开发中)
Epic: EPIC-XXX (70%)
```

### 3.3 时间格式

```
日期格式: YYYY-MM-DD
时间格式: HH:mm
预计完成: YYYY-MM-DD (周几)
```

## 5. 使用流程

### 5.1 每日记录流程

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 打开模板                                            │
│  → 打开 /tmp/daily_standup_{date}.md                        │
│  → 复制极简版模板                                            │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 2: 填写内容（2-3分钟）                                 │
│  → 今日完成 (参考昨日计划)                                   │
│  → 进行中 (参考 Neo4j 状态)                                 │
│  → 明日计划 (参考 Epic 交付计划)                             │
│  → 阻塞/风险 (有则记录，无则写"无")                          │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  Step 3: 保存并发送（1分钟）                                 │
│  → 保存到 /tmp/                                             │
│  → 如有阻塞问题 → 发送飞书通知                               │
│  → 同步到周报素材                                            │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 阻塞问题处理

```
有阻塞问题
    │
    ▼
记录到站会记录 ⚠️ 部分
    │
    ▼
发送飞书通知给相关人
    │
    ▼
升级给派蒙/钟离（如需支援）
```

## 7. 与其他 SOP 的衔接

### 7.1 与 SOP-S10 周报衔接

- 站会记录积累 → 周报"本周完成"素材
- 每日进度 → 周报"进行中"素材
- 明日计划 → 周报"下周计划"素材

### 7.2 与 SOP-S12 风险预警衔接

- 站会记录风险 → 触发风险预警
- 风险状态更新 → 同步到风险跟踪表

### 7.3 与 SOP-S13 每日工作流衔接

- 站会是每日工作流的傍晚环节
- 站会记录是健康检查的补充（轻量级状态同步）

## 8. 常见问题

| 问题 | 解决方案 |
|:---|:---|
| 忘记记录 | 第二天早上补记，保证素材不丢失 |
| 内容太多 | 坚持极简版，最多 5 行 |
| 有阻塞不会升级 | 立即升级，不要等到周报 |
| Neo4j 状态不准 | 站会前先快速查询状态 |
