## 1. 概述

### 1.1 目标

识别、评估、跟踪、应对项目风险，降低风险影响

### 1.2 触发时机

| 触发类型 | 说明 | 优先级 | 触发信号 |
|:---|:---|:---:|:---|
| 项目启动 | 新项目初始化 | P0 | 项目创建 |
| 定期检查 | 周报时同步 | P1 | SOP-S10周报 |
| 风险事件 | 突发风险 | P0 | 人工报告/系统告警 |
| 每日工作流 | SOP-S13每日检查 | P1 | 定时触发 |

### 1.3 输入

| 输入项 | 必填 | 说明 |
|:---|:---:|:---|
| 项目计划 | ✅ | 目标、里程碑 |
| 历史风险数据 | ✅ | 上次复盘记录 |
| 团队反馈 | ✅ | 实时输入 |

### 1.4 输出

| 输出项 | 状态 | 说明 |
|:---|:---:|:---|
| 风险清单 | ⏳待产出 | 所有识别的风险 |
| 风险预警 | ⏳待产出 | 触发预警时 |
| 应对措施 | ⏳待产出 | 已制定的措施 |

## 2. 处理流程

### 步骤 1: 风险识别

**前置条件**：触发时机满足

**识别方法**：

| 方法 | 说明 |
|:---|:---|
| 头脑风暴 | 团队讨论可能的risks |
| 检查表法 | 基于历史风险清单检查 |
| SWOT 分析 | 分析优势/劣势/机会/威胁 |
| 专家访谈 | 向有经验的人请教 |

**风险分类**：

| 类型 | 说明 |
|:---|:---|
| 范围风险 | 需求变更、范围蔓延 |
| 进度风险 | 延期、资源不足 |
| 质量风险 | 缺陷多、质量不达标 |
| 技术风险 | 技术方案不可行 |
| 人员风险 | 人员流动、能力不足 |
| 外部风险 | 政策变化、供应商问题 |

**风险记录表**：

| 风险ID | 风险描述 | 类型 | 影响 | 概率 | 等级 |
|:---|:---|:---|:---:|:---:|:---:|
| {{id}} | {{desc}} | {{type}} | {{impact}} | {{prob}} | {{level}} |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 无法识别任何风险（全新项目无参考） | 暂停，使用通用风险检查表补充，记录"需专项评审" |
| E2 | 风险数量>20 | 降级：按影响×概率排序，取前20个，其余归档待观察 |
| E3 | 风险描述模糊 | 记录warning，补充描述或标注需明确 |

---

### 步骤 2: 风险评估

**前置条件**：步骤1完成

**评估维度**：

| 维度 | 说明 |
|:---|:---|
| 影响程度 | 对项目目标的影响大小 |
| 发生概率 | 风险发生的可能性 |
| 可控性 | 风险是否可控 |

**风险等级计算**：

```
风险等级 = 影响程度 × 发生概率

等级定义：
- 高：等级 >= 6
- 中：等级 3-5
- 低：等级 < 3
```

**风险矩阵**：

|  | 低概率 | 中概率 | 高概率 |
|:---|:---:|:---:|:---:|
| **高影响** | 中 | 高 | 高 |
| **中影响** | 低 | 中 | 高 |
| **低影响** | 低 | 低 | 中 |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 影响程度=0或概率=0 | 暂停，验证数据，0分风险应删除或重新评估 |
| E2 | 风险等级计算结果异常 | 降级：采用中等级默认值，记录warning |
| E3 | 缺少对比数据 | 记录warning，采用主观评估，继续 |

---

### 步骤 3: 风险应对

**前置条件**：步骤2完成

**应对策略**：

| 策略 | 说明 | 适用场景 |
|:---|:---|:---|
| 规避 | 消除风险源 | 高概率、高影响 |
| 转移 | 将风险转给第三方 | 高概率、中影响 |
| 缓解 | 降低风险概率或影响 | 中概率、中影响 |
| 接受 | 接受风险，准备应急 | 低概率、低影响 |

**应对措施表**：

| 风险ID | 应对策略 | 具体措施 | 责任人 | 完成时间 | 状态 |
|:---|:---|:---|:---|:---|:---|
| {{id}} | {{strategy}} | {{action}} | {{owner}} | {{date}} | {{status}} |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 高风险无应对措施 | 暂停，必须制定应对措施，否则不允许继续 |
| E2 | 责任人无法确定 | 降级：标注"待指派"，升级给派蒙确认 |
| E3 | 完成时间已过期 | 记录warning，更新为当前日期+合理时限 |

---

### 步骤 4: 风险监控

**前置条件**：步骤3完成

**监控频率**：

| 风险等级 | 监控频率 |
|:---|:---|
| 高 | 每天 |
| 中 | 每周 |
| 低 | 每两周 |

**预警机制**：

| 预警级别 | 触发条件 | 通知 |
|:---|:---|:---|
| 红色预警 | 高风险新发生/加剧 | 立即通知 |
| 橙色预警 | 中风险加剧 | 24h内通知 |
| 黄色预警 | 低风险加剧 | 周报中体现 |

**风险状态**：

| 状态 | 说明 |
|:---|:---|
| MONITORING | 监控中 |
| TRIGGERED | 已触发 |
| MITIGATED | 已缓解 |
| RESOLVED | 已解决 |
| CLOSED | 已关闭 |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 红色预警触发但无法联系责任人 | 暂停，升级给派蒙，2h内必须处理 |
| **E2** | 高风险监控数据丢失（>3天） | 降级：按最坏情况评估，加强监控频率 |
| E3 | 预警通知发送失败 | 记录warning，改用备用渠道 |

---

### 步骤 5: 风险复盘

**前置条件**：风险状态变为RESOLVED/CLOSED

**复盘内容**：
1. 风险识别是否及时
2. 评估是否准确
3. 应对措施是否有效
4. 需要哪些改进

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| E1 | 复盘无法完成（无记录） | 暂停，追问过程记录，补全后复盘 |
| E2 | 复盘结论与实际不符 | 记录warning，修正结论，继续 |
| E3 | 复盘建议无法落地 | 记录warning，调整建议使其可执行 |

## 3. 状态流转

```
步骤1[风险识别]
    │
    ├── ✅ done → 步骤2
    ├── ❌ failed（无法识别风险）→ [使用检查表补充]
    └── ⚠️ done（风险过多）→ 降级继续 → 步骤2

步骤2[风险评估]
    │
    ├── ✅ done → 步骤3
    └── ❌ failed（数据异常）→ [修正后继续]

步骤3[风险应对]
    │
    ├── ✅ done → 步骤4
    └── ❌ failed（高风险无措施）→ [暂停，必须制定措施]

步骤4[风险监控]
    │
    ├── ✅ done（无预警）→ 步骤5（满足条件时）
    ├── ✅ done（有预警已处理）→ 继续监控
    └── ❌ failed（红色预警无法处理）→ [升级派蒙]

步骤5[风险复盘]
    │
    └── ✅ done → [SOP完成]
```
