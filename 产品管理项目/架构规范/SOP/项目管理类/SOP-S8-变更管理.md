## 1. 概述

### 1.1 目标

管理需求变更，确保变更可控、可追溯

### 1.2 触发时机

| 触发类型 | 说明 | 优先级 | 触发信号 |
|:---|:---|:---:|:---|
| 业务方提出 | 业务侧提交变更申请 | P0 | 变更申请单 |
| 技术方案调整 | 钟离提出技术变更 | P1 | 技术变更通知 |
| 范围蔓延识别 | PM发现范围蔓延 | P0 | 健康检查报告 |
| 里程碑延期 | 触发变更评审 | P0 | SOP-S12风险预警 |

### 1.3 输入

| 输入项 | 必填 | 说明 |
|:---|:---:|:---|
| 变更申请单 | ✅ | 含变更描述、关联需求 |
| 原需求文档 | ✅ | 被变更的PRD/需求 |
| 影响评估数据 | ⚠️ | 可推断，Skill辅助 |

### 1.4 输出

| 输出项 | 状态 | 说明 |
|:---|:---:|:---|
| 变更评估报告 | ⏳待产出 | 影响范围、等级 |
| 变更审批记录 | ⏳待产出 | 审批结果 |
| 更新的 PRD | ⏳待产出 | 变更后版本 |
| 变更记录 | ⏳待产出 | 变更日志 |

## 2. 处理流程

### 步骤 1: 变更申请

**操作**：
1. 记录变更申请
2. 分配变更 ID：`CHG-{YYYYMMDD}-{序号}`
3. 记录申请人、申请时间

**变更申请单**：

| 字段 | 状态 | 说明 |
|:---|:---:|:---|
| 变更ID | ⏳ | CHG-{YYYYMMDD}-{序号} |
| 申请人 | ⏳ | |
| 申请时间 | ⏳ | |
| 变更类型 | ⏳ | 需求变更/技术调整/范围变更 |
| 变更描述 | ⏳ | |
| 关联需求 | ⏳ | REQ-XXX / Epic-XXX |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 变更描述为空 | 暂停，追问"请提供变更描述" |
| E2 | 关联需求不明确 | 降级：标注"待确认关联"，继续 |
| E3 | 变更ID格式错误 | 记录warning，自动修正 |

---

### 步骤 2: 影响评估

**前置条件**：步骤1完成

**评估维度**：

| 维度 | 评估内容 | 说明 |
|:---|:---|:---|
| 范围影响 | 影响哪些 Epic/Feature/Story | |
| 进度影响 | 是否影响里程碑 | |
| 资源影响 | 是否需要额外资源 | |
| 成本影响 | 工作量变化 | |

**评估结论**：

| 影响等级 | 说明 |
|:---|:---|
| 低 | 范围小，不影响进度 |
| 中 | 范围中等，可能影响进度 |
| 高 | 范围大，影响里程碑 |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | 关联需求不存在 | 暂停，报告"关联需求不存在"，确认变更范围 |
| **E2** | 影响范围无法确定 | 降级：标注"影响范围待评估"，按中等级处理，继续 |
| E3 | 里程碑数据缺失 | 记录warning，按无里程碑影响处理 |

---

### 步骤 3: 变更审批

**前置条件**：步骤2完成

**审批流程**：

| 影响等级 | 审批人 | 审批时限 |
|:---|:---|:---:|
| 低 | Tony | 1天内 |
| 中 | Tony + 业务方 | 2天内 |
| 高 | Tony + 业务方 + 钟离 | 3天内 |

**审批结果**：

| 结果 | 操作 |
|:---|:---|
| 批准 | 进入步骤4 |
| 拒绝 | 记录原因，通知申请人，SOP结束 |
| 搁置 | 记录状态，待后续评审 |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| E1 | 审批拒绝 | 暂停，通知申请人，记录拒绝原因，SOP结束 |
| **E2** | 审批超时（低>24h/中>48h/高>72h） | 降级：发送催审提醒，超时1.5倍后按"搁置"处理 |
| E3 | 审批人失联 | 记录warning，寻找替代审批人或升级处理 |

---

### 步骤 4: 更新文档

**前置条件**：步骤3完成（批准）

**操作**：
1. 更新 PRD 文档
2. 更新变更日志
3. 同步到 Neo4j（如涉及结构变化）
4. 通知相关方

**变更日志格式**：

| 时间 | 变更ID | 变更内容 | 审批人 |
|:---|:---|:---|:---|
| {{datetime}} | CHG-XXX | {{content}} | {{approver}} |

**异常预定义**：

| 等级 | 异常 | 处理 |
|:---:|:---|:---|
| **E1** | PRD 文档被锁定 | 暂停，报告锁定状态，需解锁后继续 |
| E2 | Neo4j同步失败 | 记录warning，继续其他更新，稍后重试同步 |
| E3 | 通知发送失败 | 记录warning，改用其他渠道通知 |

## 3. 状态流转

```
步骤1[变更申请]
    │
    ├── ✅ done → 步骤2
    └── ❌ failed（描述为空）→ [追问后resume]

步骤2[影响评估]
    │
    ├── ✅ done → 步骤3
    ├── ❌ failed（需求不存在）→ [报告问题，SOP中止]
    └── ⚠️ done（范围待评估）→ 降级继续 → 步骤3

步骤3[变更审批]
    │
    ├── ✅ done（批准）→ 步骤4
    ├── ❌ failed（拒绝）→ [通知申请人，SOP结束]
    └── ⏳ pending（审批超时）→ [催审，超时后按搁置处理]

步骤4[更新文档]
    │
    ├── ✅ done → [SOP完成]
    └── ❌ failed（文档锁定）→ [暂停，解锁后resume]
```
