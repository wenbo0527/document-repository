> **版本**: v1.0
> **日期**: 2026-05-12
> **作者**: Tony Stark
> **用途**: 说明 PRD 文档必须符合的模板规范

## 一、PRD 文档命名规范

### 1.1 文件命名

```
格式：{YYYY-MM-DD}-PRD-{Epic名称}-{版本}.md

示例：
- 2026-05-12-PRD-EPIC-DFD-SEARCH-v1.0.md
- 2026-05-12-PRD-数据管理-业务概念管理-v1.0.md
```

### 1.2 文档内部标题

```
# PRD-{Epic名称}

示例：
# PRD-EPIC-DFD-SEARCH 统一搜索
# PRD-数据管理-业务概念管理
```

### 3.6 Story 命名规范

| 层级 | 命名格式 | 示例 |
|:---|:---|:---|
| Epic | EPIC-{域}-{模块} | EPIC-DFD-SEARCH |
| Feature | FEAT-{域}-{模块}-{序号} | FEAT-DFD-SEARCH-QUERY |
| Story | Story-{模块}-{序号} | Story-SE-001 |

**规范要求**：
- Story ID 必须唯一
- Story 名称应简洁明了
- 优先级：P0/P1/P2/P3
- 状态：待开发/开发中/待评审/已完成

---

### 3.7 验收标准规范

每个 Story 必须包含验收标准，且验收标准必须满足 **SMART** 原则：

| 原则 | 说明 | 示例 |
|:---|:---|:---|
| **S**pecific 具体 | 标准清晰明确 | "列表每页展示20条数据" |
| **M**easurable 可量化 | 可衡量指标 | "响应时间<500ms" |
| **A**chievable 可达成 | 现实可实现 | "支持主流浏览器" |
| **R**elevant 相关 | 与目标相关 | "数据准确性99%以上" |
| **T**ime-bound 时限 | 有完成时限 | "页面加载<2秒" |

**验收标准必须覆盖**：
1. ✅ 功能标准 - 完成什么功能
2. ✅ 操作标准 - 如何操作
3. ✅ 数据标准 - 数据展示什么
4. ✅ 交互标准 - 交互行为

**验收标准禁止**：
- ❌ "功能正常" - 过于模糊
- ❌ "体验良好" - 无法衡量
- ❌ "满足需求" - 循环定义

### 3.8 菜单映射表（必须）

| 功能模块 | 一级菜单 | 二级菜单 | 三级菜单 | 路由路径 |
|:---|:---|:---|:---|:---|
| {{module}} | {{menu1}} | {{menu2}} | {{menu3}} | /path/to/page |

**规范要求**：
- 路由必须准确，与前端代码一致
- 菜单层级必须与实际系统一致

## 四、PRD 文档质量检查清单

### 4.1 提交前自检

| 检查项 | 说明 | 通过标准 |
|:---|:---|:---:|
| 章节完整性 | 所有必须章节都已包含 | 10个章节无缺失 |
| 命名一致性 | Epic/Feature/Story ID 格式统一 | 无重复、无错误 |
| 验收标准 | 每个 Story 有验收标准 | 100% 覆盖 |
| 路由准确性 | 菜单映射表路由正确 | 与前端代码一致 |
| 变更日志 | 每次修改已记录 | 版本号递增 |
| 状态同步 | 文档状态与实际一致 | 无过期状态 |

### 4.2 常见问题

| 问题 | 原因 | 修复方式 |
|:---|:---|:---|
| Story ID 重复 | 多人同时编写 | 统一分配 ID |
| 验收标准模糊 | 未量化 | 按 SMART 原则重写 |
| 路由错误 | 与前端不一致 | 核对前端代码 |
| 版本未更新 | 修改后忘记更新 | 建立修改习惯 |
