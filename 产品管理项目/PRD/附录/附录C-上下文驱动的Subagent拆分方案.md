## C.1 拆分原则

### 核心思想

**按「谁看的文档」拆分**，而不是按工作流程拆分。

### 旧方案问题

| 问题 | 说明 |
|:---|:---|
| 单 Agent 混杂多层信息 | 一个 Agent 需要理解全部上下文 |
| Token 消耗高 | 8,000+ tokens/请求 |
| 可复用性低 | 与流程绑定，无法独立使用 |
| 测试难度高 | 需要完整流程才能测试 |

### 新方案优势

| 优势 | 说明 |
|:---|:---|
| 每层 Agent 只看自己层 | 上下文清晰，Token 节省 62% |
| 可独立使用 | 任意 Agent 可单独调用 |
| 测试简单 | 单独测试单个 Agent |
| 可组合 | 灵活组合满足不同场景 |

## C.3 各层 Agent 详细说明

### C.3.1 产品上下文层

#### 1. 需求理解 Agent

| 属性 | 值 |
|:---|:---|
| 名称 | ProductContextAgent |
| 输入 | 原始需求（飞书消息/文档/口头描述） |
| 输出 | 结构化需求文档 |
| Token 消耗 | ~800 tokens |

**职责**：
- 理解需求背景和目标
- 提取关键实体和关系
- 生成结构化需求文档

#### 2. 产品分析 Agent

| 属性 | 值 |
|:---|:---|
| 名称 | ProductAnalysisAgent |
| 输入 | 结构化需求文档 |
| 输出 | 产品分析报告（影响范围、依赖关系、风险评估） |
| Token 消耗 | ~1,200 tokens |

**职责**：
- 分析需求影响范围
- 识别依赖关系
- 评估风险和优先级

#### 3. PRD 生成 Agent

| 属性 | 值 |
|:---|:---|
| 名称 | PRDGeneratorAgent |
| 输入 | 产品分析报告 |
| 输出 | PRD 文档（Epic/Feature/Story 结构） |
| Token 消耗 | ~1,500 tokens |

**职责**：
- 生成标准 PRD 文档
- 拆解 Epic/Feature/Story
- 定义验收标准

### C.3.2 技术上下文层

#### 4. 代码结构扫描 Agent

| 属性 | 值 |
|:---|:---|
| 名称 | CodeScannerAgent |
| 输入 | Epic/Feature 描述 |
| 输出 | 代码路径清单、技术依赖分析 |
| Token 消耗 | ~600 tokens |

**职责**：
- 扫描代码仓库结构
- 识别相关代码文件
- 分析技术依赖

#### 5. 技术拆解 Agent

| 属性 | 值 |
|:---|:---|
| 名称 | TechBreakdownAgent |
| 输入 | Epic/Feature + 代码结构 |
| 输出 | 技术拆解结果（FP、接口定义、数据库变更） |
| Token 消耗 | ~1,000 tokens |

**职责**：
- 将 Feature 拆解为 FP
- 定义接口方案
- 规划数据库变更

#### 6. 技术评估 Agent

| 属性 | 值 |
|:---|:---|
| 名称 | TechAssessmentAgent |
| 输入 | 技术拆解结果 |
| 输出 | 技术可行性报告（工时、风险、问题） |
| Token 消耗 | ~800 tokens |

**职责**：
- 评估技术可行性
- 估算开发工时
- 识别技术风险

### C.3.3 执行上下文层

#### 7. 数据同步 Agent

| 属性 | 值 |
|:---|:---|
| 名称 | DataSyncAgent |
| 输入 | Epic/Story 状态变更 |
| 输出 | Neo4j 更新 + 飞书同步 |
| Token 消耗 | ~400 tokens |

**职责**：
- 同步状态到 Neo4j
- 更新飞书多维表格
- 维护数据一致性

#### 8. 状态跟踪 Agent

| 属性 | 值 |
|:---|:---|
| 名称 | ProgressTrackerAgent |
| 输入 | Epic/Story 列表 |
| 输出 | 进度报告、预警信息 |
| Token 消耗 | ~500 tokens |

**职责**：
- 跟踪开发进度
- 生成进度报告
- 预警延期风险

#### 9. 周报生成 Agent

| 属性 | 值 |
|:---|:---|
| 名称 | WeeklyReportAgent |
| 输入 | 本周工作数据 |
| 输出 | 周报文档 |
| Token 消耗 | ~600 tokens |

**职责**：
- 汇总本周完成工作
- 生成周报文档
- 同步到飞书 |

## C.4 Agent 协作流程

### 标准流程

```
用户输入 → 需求理解 → 产品分析 → PRD生成
                              ↓
                         代码结构扫描
                              ↓
                         技术拆解 → 技术评估
                              ↓
                         数据同步 → 状态跟踪 → 周报生成
```

### 简化流程（快速路径）

```
用户输入 → 需求理解 → PRD生成 → 技术评估 → 数据同步
```

### 独立调用

任意 Agent 可独立使用：
- 只需产品分析 → 调用「产品分析 Agent」
- 只需周报 → 调用「周报生成 Agent」

## C.5 与旧方案对比

| 维度 | 旧方案 | 新方案 |
|:---|:---|:---|
| Agent 数量 | 3 个（按流程） | 9 个（按上下文） |
| 拆分逻辑 | 按工作流程顺序 | 按「谁看的文档」 |
| 上下文范围 | 单 Agent 混杂多层信息 | 每层 Agent 只看自己层 |
| Token 效率 | 8,000+ tokens/请求 | 3,000 tokens/请求 |
| Token 节省 | - | 62% |
| 可复用性 | 低，与流程绑定 | 高，可独立使用 |
| 测试难度 | 高，需要完整流程 | 低，可单独测试 |
| 适用场景 | 固定流程 | 灵活组合 |
